# 语音输入

输入框中的麦克风直接开始听写，用户授权后调用 `@kit.CoreSpeechKit` 的 `speechRecognizer`，不打开独立面板。当前系统服务支持中文离线识别，包含中文语境下的英文；界面语言切换不会改变识别语种。无需 API Key，不把音频发送给配置的模型服务，也不在应用中保存录音。

使用系统实时录音模式（`recognitionMode: 0`）、长语音模式（`recognizerMode: 'long'`）与 16 kHz / 单声道 / 16 bit PCM。短暂停顿不会结束整次输入；每次最长 10 分钟，到时停止。部分结果替换当前子句，最终子句追加，避免逐字结果重复。

- 麦克风采用用户提供的 VoicePill 样式，使用 ArkUI 实现，无 React/WebView 依赖。200 ms 展开为胶囊，显示计时和活动历史；按下轻微缩小，左滑跟手显示取消。波形由系统 VAD 开始/结束事件驱动活动动效，静音时回落；接口不提供音量，这不是精确音量计。Canvas 独立绘制，避免每帧重建聊天列表。
- 点按开始、再次点按停止；按住 300 ms 开始，松手停止。左滑 64 vp 或点“取消”撤销本次输入。键盘/辅助功能可点按启停，取消按钮同样可访问。
- 识别结果实时写入 composer 草稿，不自动发送。停止时调用 `finish`，等待最后结果；正常结束且没有识别到文字时直接收起胶囊，不显示提示，原草稿保持不变。识别期间暂时禁止键盘修改、发送及排队，停止后恢复编辑。
- 取消只回滚本次听写，原草稿保留；期间发生其他草稿修改时不覆盖。切到后台、进入历史/设置、切换会话或组件卸载会释放引擎并保留已经写入的文字。授权和初始化期间取消后，迟到回调不会开始录音，已创建的引擎立即释放。
- 检查会话身份和 24000 字符上限；超过上限停止录音，保留已输入的草稿并提供“复制识别文字”，不静默截断或覆盖其他会话。
- 拒绝授权、设备无系统能力、引擎错误和初始化/结束超时均有明确提示。识别中途失败保留已写入的文字。

声明 `ohos.permission.MICROPHONE`，仅在点击语音输入或主动使用桌面“语音输入”快捷入口后申请，仅在前台使用。拒绝后显示“允许麦克风”，用户主动点击才调用 `requestPermissionOnSetting` 打开系统权限设置弹窗。不申请后台录音权限。

## 回答朗读与桌面快捷入口

回答生成结束后，打开回答的“更多”菜单或长按回答，选择“朗读回答”。朗读期间，输入框上方显示状态和“停止朗读”；也可从同一消息菜单停止。使用系统离线文本转语音，不需要模型 API Key。正文中的 Markdown 格式会转为文字，跳过代码块、图片地址和交互 UI 数据；长回答分段播放。包含汉字时使用中文音色，否则使用英文音色；英文音色需要设备已安装，缺失或引擎失败时显示系统错误，不自动下载音色。

一次只朗读一条回答，开始另一条会停止前一条。开始听写、进入历史或设置、切换会话、应用进入后台及组件卸载时停止朗读；开始朗读也会结束听写并保留已经写入的草稿。

长按桌面 Tinybot 图标，可选择“新对话”或“语音输入”。两者都先保存原草稿，再创建不属于项目的新对话；“语音输入”随后启动听写，文字不自动发送。冷启动等待本地会话加载完成；任务进行中或保存失败时提示先完成操作，不中断任务，也不延迟自动开始录音。

`node scripts/test-answer-speech-native.cjs` 验证朗读分段、取消、迟到回调、后台释放、系统失败和快捷入口的单次分发；真实音色及音频输出仍需设备验证。
