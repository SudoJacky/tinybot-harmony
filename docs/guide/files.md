# 文件与工作区

这页说明会话绑定的工作区（Workspace）在什么位置、如何浏览与编辑文本、怎样导入材料并导出到系统文件夹，以及“助手改了文件”这件事如何审阅、保留或恢复。

## 工作区在哪里

每个会话绑定一个目录，路径在运行时推导，不写死在配置里：

```text
<应用级 filesDir>/workspace/
├── <会话ID>/                普通会话各自的目录
│   ├── 笔记-1007-1530.md
│   └── .tinybot-review/     审阅基线（隐藏目录）
└── project-<项目ID>/        项目共享目录，项目内所有会话共用
```

| 会话类型 | 目录 | 共享范围 |
| --- | --- | --- |
| 普通会话 | `workspace/<会话ID>` | 只有这一条会话 |
| 项目会话 | `workspace/project-<项目ID>` | 该项目内所有会话 |

- 目录位于应用沙箱内，不需要存储授权，也不出现在系统文件管理器的公共目录里。
- 普通会话启动时会补建自己的目录；项目目录缺失时明确报错“项目工作区不存在，请从备份恢复。”，不会静默创建空目录。
- 路径会逐级检查，拒绝越界路径与符号链接；目录里的符号链接条目在列表里显示为“链接 · 不支持打开”。

## 从哪里打开

| 入口 | 打开的内容 |
| --- | --- |
| 输入区“+ → 工作区” | 当前会话的工作区根目录 |
| 更多菜单 →“工作区文件” | 同上 |
| 项目分组菜单 →“项目文件” | 项目共享目录，标题为“项目文件 · 项目名”；项目没有可用会话时会先新建一条 |
| 回答里的文件卡片 | 直接打开对应文件 |
| 文件交付卡片 | 预览、分享、导出当前文件 |

“项目文件”打开的是该项目最近更新的未归档会话；项目内会话看到的都是同一份文件。

## 浏览

- 顶部是面包屑，点任意一级返回该层；系统返回键先返回上一级目录，再离开页面。
- 下拉刷新重新读取目录；文件夹排在文件前，各自按名称排序。
- 单层最多加载 200 项，超出的部分提示“仅显示前 200 项”。
- 图片文件直接以图片预览；Markdown 渲染排版；CSV/TSV 显示为表格；其余文本按等宽字体显示，可长按选择。
- 读取失败时页面内显示错误条，可关闭后重试。

## 新建、编辑与删除

| 操作 | 行为 |
| --- | --- |
| 新建笔记 | 在当前位置创建空 `.md`，命名 `笔记-MMDD-HHmm.md`，重名自动加 ` (2)`，随后直接进入编辑 |
| 编辑 | 文本在编辑器中最多 32000 字符；编辑中标题显示“编辑中”或“编辑中 · 未保存” |
| 保存 | 覆盖写入后重新读取基线，提示“已保存” |
| 放弃 | 有未保存修改时返回会询问“放弃未保存的修改？”，可继续编辑或放弃 |
| 删除 | 二次确认“删除后无法恢复”，删除后关闭预览并刷新列表 |

图片文件只能预览，没有编辑入口。文件行左滑提供分享、导出、删除；预览页底部提供分享、导出与删除，文本文件另有引用。

## 导入材料

“导入文件”使用系统文件选择器，一次最多 5 个，可选后缀为 `.txt`、`.md`、`.csv`、`.tsv`、`.json`、`.log`、`.pdf`、`.docx`、`.xlsx`、`.pptx`。

- 文本文件按 UTF-8 完整读入；非 UTF-8 或包含空字符的文件会拒绝导入，并给出明确错误。
- PDF 与 Office 文档提取文字后以 `.txt` 形式保存，PDF 最多 100 页、原文件最多 8 MB；不保留排版，也不做扫描件 OCR。
- 文件名会去掉路径分隔符等非法字符，重名自动加序号，不会覆盖已有文件。
- 导入结束提示“已导入 N 个文件”。导入是复制一份到工作区，原文件位置不受影响。

## 保存到系统文件夹与分享

- **导出**：打开系统保存选择器，你选好位置后才写入；取消选择不会产生文件。源文件读取上限 20 MB。
- **分享**：先复制一份到应用缓存并清洗文件名，再交给系统分享面板，因此分享后再修改工作区文件不会改变已分享内容。
- 两者都对当前文件生效，不改变工作区里的原件。

## CSV / TSV 表格预览

扩展名为 `.csv` 时按逗号分列，`.tsv` 时按制表符分列，第一行作为表头，其余作为数据行，表格最高 4000 vp 后内部滚动。预览是只读的：需要改数据时点“编辑”修改原文，保存后重新打开即可看到新表格。表格上选中的文字同样可以引用到草稿。

## 修改审阅：基线、差异、保留与恢复

文件被写入前，应用会在工作区的 `.tinybot-review/` 下保存一份基线（Baseline）：`<编码后的相对路径>.json`，记录路径、修改前是否存在、修改前内容。同一条路径只保存第一次修改前的状态，后续写入不覆盖基线。基线由写入动作触发，因此无论改动来自助手工具还是你在文件面板里的保存，只要基线存在，打开该文件就会显示审阅卡。

打开一个带基线的文件时，预览页出现审阅卡：

| 场景 | 卡片文案 | 按钮 |
| --- | --- | --- |
| 普通会话、已有文件 | 助手修改了这个文件 / 确认保留修改，或恢复到修改前的版本 | 看差异、保留修改、恢复原版 |
| 普通会话、新建文件 | 助手修改了这个文件 / 这是助手新建的文件 | 看差异、保留修改、删除文件 |
| 项目会话 | 项目中的待审修改 / 这里包含项目内各会话和文件编辑的累计修改 | 同上，恢复前额外提示可能包含其他会话的改动 |

- **看差异**在“看内容”和“看差异”之间切换；差异按行显示，删除行红色 `-`、新增行绿色 `+`，分段处有 `@@` 标记，可复制。
- **保留修改**删除这条基线，文件保持当前内容，之后不再提示。
- **恢复原版**把文件写回基线内容；新建文件则直接删除。恢复前会核对你看到的内容与磁盘当前内容是否一致，不一致时报“文件已变化，请重新打开并检查。”，不做强制覆盖。
- “恢复原版”会弹出确认，“保留修改”点击即生效；项目会话的恢复确认框会说明影响范围是项目级累计修改。

## 本轮修改

每条回答结束后，如果本轮真的改过文件，末尾展示“本轮修改”：

- 按路径比较“本轮首次成功修改前”与“最后一次写入后”的内容，包含工具编排里的子调用。
- 改回原文的文件不计入净变化；新建的空文件仍会列出。
- 可展开文件清单与分页差异；这份快照随回执一起保存，重启后不依赖当前文件，也不会进入模型上下文。
- 旧回执没有本轮快照时不推算汇总；用户审阅用的基线与之独立。

## 写入规则

| 规则 | 表现 |
| --- | --- |
| 原子替换 | 先写同目录临时文件、`fsync`，再重命名覆盖目标；失败时清理临时文件 |
| 文本约束 | 只处理 UTF-8 文本，拒绝空字符；不能写目录或符号链接 |
| 覆盖前必须读取 | 本轮没有成功读取过的已有文件，只能创建新文件；直接覆盖返回 `FS_NOT_OBSERVED` |
| 版本校验 | 读取时记录 SHA-256，写入时比对；期间文件被改动则返回 `FS_STALE_VERSION`，要求重新读取 |
| 串行写入 | 同一路径的写入排队执行，不同文件可并行 |

原子替换与文本约束对所有写入生效；覆盖前必须读取、版本校验与串行队列同时约束助手的工具调用，界面里的保存只做原子替换。完整的错误码与恢复建议见[回执与错误](/reference/receipts)。

## 边界

- 文件工具只能访问当前会话绑定的工作区，看不到其他会话目录、模型配置或密钥。
- 没有 Shell、跨应用控制或任意外部目录访问；外部文件只能通过系统选择器，以你选中的 URI 为范围。
- 列目录每次最多 200 项，内容搜索每次最多扫描 200 个文件并返回 100 处匹配，读取每次最多 2000 行或 50 KiB，可继续读取。

项目共享的归属规则见[项目与共享工作区](/guide/projects)，备份如何带走文件见[云备份](/guide/cloud-backup)。
