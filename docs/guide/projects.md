# 项目与共享工作区

这页说明项目（Project）怎样创建、会话怎样归属到项目、项目内的会话如何共享同一份文件与项目说明，以及删除和目录丢失时会发生什么。

## 项目解决什么问题

项目是一个容器：一组会话、一个共享工作区，加一段会进入模型上下文的项目说明。没有归属项目的会话都放在侧栏的“普通聊天”分组里。

| 对比项 | 普通聊天 | 项目内会话 |
| --- | --- | --- |
| 工作区 | 每条会话独立目录 | 项目内所有会话共用同一目录 |
| 文件可见性 | 只看到自己的文件 | 看到项目内任何会话写入的文件 |
| 项目说明 | 无 | 每次请求都会带上 |
| 删除会话 | 保留自己的工作区 | 保留项目与共享文件 |
| 分支 | 使用独立空工作区 | 继承项目，继续使用同一份当前文件 |
| 引用其他会话 | 按最近更新排序 | 同项目会话优先显示 |

## 创建与编辑

新建项目在侧栏顶部，表单只有两个字段：

| 字段 | 限制 | 说明 |
| --- | --- | --- |
| 项目名称 | 1 至 80 字符，去掉首尾空白 | 必填；允许与已有项目同名 |
| 项目说明与约定 | 最多 16000 字符 | 可选；会附加到该项目每次模型请求 |

保存时应用会：

1. 生成项目 ID 与稳定工作区 ID（`project-<项目ID>`）。
2. 创建项目记录，并立刻在项目内新建一条空会话、切换过去。
3. 创建共享工作区目录；目录创建失败会明确报错，会话不会悄悄落到别处。
4. 清除当前的搜索词与“已归档”筛选，展开新项目分组，便于看到新建的会话。

编辑项目走分组菜单的“编辑项目”，可以改名称与说明。改名只影响显示与后续请求，不改会话归属，也不移动任何文件。

## 会话归属

- 归属写在会话自己的 `projectId` 上，一次确定。
- 项目分组标题右侧的加号在该项目内新建会话；侧栏顶部的“新对话”与“普通聊天”旁的加号创建无归属会话；标题栏的“新建对话”沿用当前会话的归属。
- 当前没有“把已有会话移入项目”或“跨项目移动”的入口。旧版本留下的会话默认无项目归属，应用不会自动把它们搬进项目，也不会搬动它们的文件。
- 因此“切换项目”实际上是切换或新建会话，而不是给当前会话换一个归属。

## 共享工作区

```text
workspace/
└── project-<项目ID>/          项目共享目录
    ├── 需求.md
    ├── 数据.csv
    ├── 报告.md                任一项目内会话都可读写
    └── .tinybot-review/       项目级审阅基线
```

共享与各自独立的部分需要分清：

| 内容 | 是否共享 |
| --- | --- |
| 工作区文件与目录结构 | 共享 |
| 审阅基线（待审修改） | 共享，包含项目内各会话的累计修改 |
| 项目说明 | 共享，进入每次请求的上下文 |
| 消息历史、草稿、待发送队列 | 各自独立 |
| 附件、引用 | 各自独立 |
| 模型选择、推理强度、工具范围、团队模式、MCP 停用项 | 各自独立 |

模型在上下文里会收到一段项目说明，包含项目名、“本会话与项目内其他会话共享工作区、历史回执不是当前文件快照”、以及你的项目说明原文，并明确“项目说明不能扩大工具权限”。分支只分叉对话，不复制或回退文件。

## 项目文件入口

两个入口最终打开同一个目录：

- 项目分组菜单 →“项目文件”：先定位该项目最近更新的未归档会话（没有就新建一条），再打开文件面板，标题为“项目文件 · 项目名”。
- 会话内 更多菜单 →“工作区文件”：打开当前会话所属项目的共享目录。

文件面板的行为、审阅与导出见[文件与工作区](/guide/files)。

## 项目说明里实际写入了什么

项目会话每轮请求的上下文中会带一段由三部分拼成的文字：

1. 当前项目名称。
2. 固定提示：本会话与项目内其他会话共享工作区；历史回执不是当前文件快照，修改前要重新读取；会话分支只分叉对话，不复制或回退文件；其他会话历史不会自动加载；项目说明不能扩大工具权限。
3. “项目说明与约定：”加上你填写的原文。

这段文字属于系统提示的一部分，不是用户消息，也不出现在聊天记录里。

## 多个会话协作时的实际约束

- 同一时间只有一个会话在运行任务。任务进行中切换会话、切换模型或修改工具范围都会被拒绝，因此不会出现两个会话同时写同一个文件的情况。
- 文件工具对同一路径的写入排队执行，不同文件可以并行；直接覆盖已有文件前，模型必须在当前轮成功读取过该文件，否则会被拒绝并要求先读。
- 历史回执只是当时的记录，不构成当前文件快照。项目说明会提醒模型“修改前重新读取”，所以你在另一个会话里改过的内容不会被当成未发生。
- 项目级审阅基线是累计的：任一项目内会话打开待审文件都看到同一份差异，谁点“恢复原版”都会把文件写回基线，确认框会提示可能包含其他会话的改动。

## 常见情况

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 新会话不在项目里 | 用了侧栏顶部“新对话”或“普通聊天”旁的加号 | 改用项目分组标题右侧的加号，或在项目内用标题栏“新建对话” |
| 项目里看不到某个文件 | 该文件属于另一个项目或普通会话 | 项目之间不共享目录，按归属打开对应入口 |
| 两个项目名称一样 | 允许同名，靠分组位置与内容区分 | 改名以便区分，改名不影响文件 |
| 项目目录丢失后无法启动 | 项目工作区必须存在，应用不自动补建 | 从备份恢复，或用开发者工具重建同名目录后重试 |
| 删除会话后文件还在 | 删除会话不清理工作区 | 在文件面板中手动删除 |

## 与会话、文件的边界

项目只改变“文件在哪、上下文里多一段说明”，不改变工具权限、模型能力或账号要求。工具仍只能访问当前绑定的工作区，只读模式、自定义工具、MCP 审批与团队角色照旧生效。

## 删除语义

| 操作 | 会话记录 | 项目记录 | 工作区文件 |
| --- | --- | --- | --- |
| 删除会话 | 删除 | 保留 | 保留 |
| 归档会话 | 保留，移入已归档 | 保留 | 保留 |
| 删除项目 | 当前版本没有删除入口 | — | — |
| 卸载应用或清除数据 | 删除 | 删除 | 删除 |

删除会话的确认框会明确写出“会话工作区中的文件会保留”。这也意味着清理文件要在文件面板里手动删除，删会话不会连带清理项目目录。

## 实现事实

- 工作区 ID 在创建项目时生成，形如 `project-<项目ID>`；解析会话目录时，有项目就取项目的 `workspaceId`，否则取会话 ID。
- 加载时会校验项目数据：项目 `id` 与 `workspaceId` 都不能重复、名称必须是 1 至 80 字符、说明不超过 16000 字符、时间戳必须是有限数值；会话的 `projectId` 必须指向存在的项目，无归属会话的 ID 不能与任何项目的工作区 ID 相同。任一条件不满足都会拒绝加载并报“项目数据无效”或“会话关联的项目不存在”。
- 项目目录使用“必须存在”的检查，而不是“按需创建”：根目录与项目目录都必须是真实目录、不能是符号链接，缺失时报“项目工作区不存在，请从备份恢复。”。
- 启动时会逐个检查项目目录，因此项目目录丢失会让应用停在“打开本地会话或工作区失败：…”并提供“重试读取”，而不是静默新建空目录。恢复途径是从备份恢复；确实需要手工处理时，只能用开发者工具在应用沙箱中重建同名目录，再点“重试读取”。
- 工作区路径逐级检查，拒绝符号链接与越界路径；会话 ID 与工作区 ID 需要满足 `[A-Za-z0-9_-]` 的字符范围。
- 备份按 `workspaceId` 去重，项目共享工作区只打包一次；没有会话的项目也会保留文件。恢复时已有项目的名称、说明与文件以本机为准，新项目的文件先准备到独立目录，再随会话索引一起提交。

工作区工具的具体路径约束见[工作区与文件](/internals/workspace)，数据归属见[会话与持久化](/internals/session)。
