# 团队协作

聊天里的团队模式让主 Agent 把一部分工作分给多个员工并行执行，再把结果收回同一条回答。这页说明它和普通会话的差别、招募与交接的实际规则、停止与恢复的语义，以及团队用量记在哪里。

## 与普通会话的区别

| 方面 | 普通会话 | 团队模式 |
| --- | --- | --- |
| 执行者 | 主 Agent 单独完成 | 主 Agent 招募 1–8 位员工，自己继续工作并负责最终整合 |
| 工具 | 当前启用的一组工具 | 主 Agent 增加 `team_*` 协调工具；员工按权限范围另用一套工具 |
| 记录 | 一条助手消息的计划与步骤 | 主 Agent 的计划步骤，加上每份任务各自的执行记录与尝试次数 |
| 回答 | 直接在主聊天中生成 | 最终回答仍在主聊天中生成；员工不能向用户发布最终图表或文件卡片 |
| 用量 | 计入本会话 | 主 Agent 请求计入原会话与全局账本；员工请求带 `team_task` 用途单独归集 |
| 可见性 | 会话本身 | 团队卡片挂在发起它的那条助手消息上，历史团队只读 |

团队模式没有独立页面与菜单入口，全部收在聊天中。团队工具只能访问当前聊天的团队；`runId` 不是模型编造路径，归属由当前会话决定。

## 入口与模式

在输入框发送 `/team` 选择命令，或直接发送 `/team 目标`（也兼容 `@team`）。单独发送命令只启用模式，不调用模型；模式保存在当前会话，后续消息继续可用，输入框上方可关闭当前模式。

“团队模式”按钮只在键盘输入时显示，收起键盘或切到语音输入时隐藏；隐藏不会改变已经选定的模式。

## 招募与调度

主 Agent 通过 `team_recruit` 招募员工并立即在后台执行任务，返回后自己可以继续工作。追加招募时提供 `runId`，只传新成员与新任务；追加不能改变目标或并行上限。

| 对象 | 约束 |
| --- | --- |
| 团队目标 | 非空，最多 12000 字符 |
| 员工 | 1–8 位；`id` 限字母、数字、`_`、`-`，1–120 字符；显示姓名最多 60 字符；职责最多 4000 字符 |
| 任务 | 1–32 个；标题最多 160 字符；指令最多 8000 字符；依赖最多 32 个且必须存在、不重复、不指向自身、无环 |
| 并行上限 | 默认 2，范围 1–4 |
| 同时运行的团队 | 本轮最多 4 个 |
| 同一员工 | 串行处理任务，不会同时跑两个任务 |

员工未提供显示姓名时应用会自动补名，以返回的 `displayName` 为准；同一团队尽量避免重名。聊天团队由主 Agent 汇总，因此不设置“最终员工”；非聊天团队的每个任务必须通过依赖关系汇入最终任务。

主 Agent 与员工共用一条工具通道（`TeamToolLane`）：并发的读取类工具可以同时通过，排他工具会等待此前读取结束并阻塞后续调用。这样工作区写入与确认对话框不会同时发生。

一次典型的团队执行按下面的顺序推进：

```text
用户目标
  └─ 主 Agent 招募成员、提交任务（team_recruit）
       ├─ 任务依赖满足且并行额度未满 → 派发给对应员工
       │    ├─ 员工执行工具调用，写入本会话工作区
       │    └─ 员工提交交接（team_complete_task）
       ├─ 主 Agent 继续自己的工作或等待（team_wait）
       └─ 全部任务结束 → 主 Agent 核验交接并在同一轮整合
```

只有依赖全部成功的任务才会被派发；依赖文本与摘要会作为证据放进员工的用户消息，员工据此判断可用输入。

## 工具

主 Agent 可用的协调工具：

| 工具 | 作用 |
| --- | --- |
| `team_recruit` | 招募员工并提交任务；新团队传目标，追加时传 `runId` |
| `team_wait` | 等待已提交交接或团队结束；按提交事件唤醒，不返回空超时 |
| `team_inspect` | 立即查看状态与已提交结果，`afterSequence` 翻页 |
| `team_read_result` | 读取或核验某份交接；指定 `artifactIndex` 时重新读取文件并比对 |
| `team_control` | `pause` 停止派发、`cancel` 停止团队、`retry` 排队重试指定任务 |
| `team_resume` | 继续已暂停或已排队重试的团队 |

员工侧另有三个工具：`team_complete_task` 提交交接，`team_list_messages` 与 `team_read_message` 读取本团队已提交的交接。员工如果调用范围外的工具会收到“员工没有此工具权限”，不会被执行。

## 权限范围

成员可指定 `toolProfile`，不指定时为 `execution`。

| 范围 | 可用工具 |
| --- | --- |
| `execution` | 继承当前已启用的工作工具，但过滤掉所有 `team_*` 工具 |
| `research` | 读取类工具，加上 `read_web`、`search_web`、`read_reference`、`write_file`、`edit_file` |
| `review` | 仅读取类工具：文件读取与检索、附件、Skill、更新计划、代码沙箱 |

所有范围都带有 `team_complete_task`、`team_list_messages`、`team_read_message`。员工继承主 Agent 的模型与会话工作区，不能继续招募，也不能向用户发布最终图表。

## 交接

员工必须调用 `team_complete_task` 才算完成；没有交接时任务不会被标为成功。交接包含摘要、未解决事项与实际产物路径。

| 字段 | 限制 |
| --- | --- |
| 摘要 | 最多 12000 字符 |
| 未解决事项 | 最多 20 条，每条最多 2000 字符 |
| 产物 | 最多 8 个文本文件，路径为工作区相对路径且不能重复 |
| 单份产物 | 读取并核验后最多 65536 字符 |
| 交接总量 | 一次交接合计最多 128000 字符 |

交接成功落盘后才对主 Agent 可见。主 Agent 读取产物时会重新读取当前文件并与交接时的副本比对；文件已变化会明确报错，不会把新版当作旧结果。调用 `team_complete_task` 之后员工不能再调用工具，也不应再修改文件。

交接文本保留原始内容。主 Agent 在整理前先尝试结束本轮时，应用会等待在跑的员工并把这些交接作为数据交回，因此整合仍在同一轮完成。

## 停止、暂停与恢复

| 操作 | 行为 |
| --- | --- |
| 停止聊天 | 取消本轮启动的所有员工并等待收尾，不再派发新任务 |
| 暂停 | 停止派发新任务，等待正在执行的员工完成 |
| 重试 | 只接受失败、停止或中断的任务；需要团队已停止且明确列出任务 ID，重试只排队，随后调用 `team_resume` |
| 取消 | 立即中止该团队的所有员工，任务标为已停止 |
| 恢复 | 只允许任务状态为“等待执行”或“成功”的团队继续；执行中的任务被标为中断时不会自动重放 |

失败、中断或取消的任务必须明确重试才能继续，应用不会自动重放文件或远程副作用。应用重启后模式、团队、尝试次数与交接都会保留，运行中的任务标为中断；手机系统终止应用后不承诺继续运行。

团队状态与任务状态的显示名称：

| 状态 | 含义 |
| --- | --- |
| 待确认 / 执行中 / 已暂停 | 已提交但未开始、正在派发、暂停派发 |
| 已完成 / 失败 / 已停止 / 已中断 | 全部任务成功、有任务失败或调度出错、被停止、应用退出时尚未完成 |
| 等待执行 / 成功 | 单个任务尚未派发、单次尝试成功 |

## 界面与用量归属

团队卡片默认展示成员与完成进度，原地展开后可查看任务、交接摘要、未解决事项、产物路径与用量，任务详情里可继续展开执行记录。最终回答始终在主聊天中，文件从本会话工作区查看。

- 团队卡片汇总员工步骤中已报告的输入与输出 Token，并单独列出未报告的步数，不做估算补齐。
- 主 Agent 的请求照常记在原聊天与全局 Token 用量里，按原轮次归属，不另起一份账。
- 员工请求的用途为团队执行，并记录团队 ID、任务 ID、任务标题、成员名、尝试 ID 与第几次尝试。
- 备份包含团队记录与文本交接；恢复时重映射所属消息、团队与模型引用。

原有手动团队记录以聊天末尾的“历史团队”卡片保留只读查看，不能继续追加任务；新任务需要通过主 Agent 重新招募。
