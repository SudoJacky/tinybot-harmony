# 语音输入

输入框里的麦克风用系统语音识别把话变成文字，识别结果默认直接发送。这页说明按住说话的完整手势、识别失败时的表现、回答朗读，以及语音能力与系统接入的边界。

## 入口与模式

点击输入框右侧的麦克风，输入区切换为“按住说话”。此时文本框隐藏，出现一条按住按钮和返回键盘的按钮；点击键盘图标回到文字输入。

语音模式属于输入区状态：切换会话不会自动退出，完成一次“编辑”转写或识别失败并写回草稿后回到文字输入。打开会话抽屉、展开浏览器时，识别中会结束本次听写。

## 手势

| 手势 | 结果 |
| --- | --- |
| 按住按钮 220 毫秒 | 开始录音与识别，按钮文案变为“松开发送” |
| 按住后向左滑到“取消” | 按钮高亮为危险色，松手撤销本次输入 |
| 按住后向右滑到“编辑” | 按钮高亮为主题色，松手把识别文字转成草稿并回到键盘 |
| 松手（默认区域） | 结束识别，识别完成后发送 |
| 按下后不到 220 毫秒就松手 | 不开始录音，也不产生文字 |
| 录音期间再次出现第二根手指 | 取消本次录音，与滑到“取消”后松手等价 |

录音时屏幕底部展开覆盖层：顶部是可滚动的实时转写文本（最高 120），中间是随语音活动起伏的球体，底部是“取消”与“编辑”两个投放目标。波形由系统 VAD 的开始/结束事件驱动，接口不提供音量，因此它不是精确的音量表。

## 识别与写入

识别使用 `@kit.CoreSpeechKit` 的 `speechRecognizer`，语言固定为 `zh-CN`，界面语言切换不会改变识别语种，中文语境中的英文同样会转写。

- 部分结果替换当前子句，最终子句累加，避免逐字结果重复。
- 未结束时不会写入草稿，也不会提前发送；松手后才进入整理阶段，按钮显示“正在整理识别文字…”。
- 识别完成后按松手位置处理：发送、转为草稿并回到键盘，或取消。
- 转为草稿时保留原有草稿：原文与识别文字之间按需补一个换行；原草稿被外部修改时停止应用，并提示“草稿已修改，语音输入已停止。”
- 发送时若当前无法发送，会保留为草稿并提示“识别文字已保留为草稿，当前无法发送。”；任务正在进行且允许排队时改为加入待发送队列。
- 识别期间文本框隐藏、键盘输入与发送入口都不可用，结束后恢复。
- 正常结束但没有识别到文字：默认区域松手时提示“未识别到文字，请重试。”，编辑区域松手时直接回到键盘。

一次听写经过以下阶段，界面文案随阶段变化：

| 阶段 | 含义 | 按钮文案 |
| --- | --- | --- |
| `idle` | 未开始 | 按住说话 |
| `preparing` | 已授权，正在创建引擎 | 准备中，请继续按住 |
| `listening` | 正在录音与识别 | 松开发送 / 松开取消 / 松开转为文字 |
| `finishing` | 已松手，等待最后结果 | 正在整理识别文字… |
| `complete` | 引擎正常结束 | 回到按住说话 |
| `error` | 失败，已识别文字写回草稿 | 显示错误提示；成功写回时回到文字输入 |

## 与其他输入方式的关系

```text
按住 220ms
  └─ 录音中：转写实时显示在覆盖层，草稿不变
       ├─ 滑到取消并松手 → 丢弃本次转写
       ├─ 滑到编辑并松手 → 合并进草稿，回到键盘
       └─ 默认区域松手  → 等待最终结果
            ├─ 可以发送 → 直接发送
            ├─ 正在生成且可排队 → 加入待发送队列
            └─ 其他情况 → 保留为草稿并提示
```

- 附件、引用与其他草稿内容不受影响：转草稿时只追加文字。
- 语音输入不会自动切换当前会话，也不会跨会话保存识别结果。
- 开始朗读回答会先结束听写；开始听写会先停止朗读。

## 时长与限制

| 项目 | 值 |
| --- | --- |
| 按住启动阈值 | 220 毫秒 |
| 准备阶段超时 | 15 秒，超时提示“系统语音识别响应超时，请重试。” |
| 单次录音上限 | 10 分钟；到时停止，引擎自身也设置了同样的上限 |
| 结束等待 | 10 秒；超时按识别失败处理 |
| 草稿上限 | 24000 字符，超过时停止写入并提示复制识别文字 |
| 音频格式 | 16 kHz、单声道、16 bit PCM |
| 保存录音 | 不保存，不发送给配置的模型服务 |

## 权限

语音输入声明 `ohos.permission.MICROPHONE`，只在用户按住说话、真正开始录音时申请，并且只在前台使用。应用不申请后台录音权限。

拒绝授权后，错误提示的操作按钮变为“允许麦克风”；只有用户主动点击才会调用系统权限设置弹窗，授权成功后仍需重新按住说话才会开始录音。若草稿写入失败，同一个位置改为“复制识别文字”，把本次转写复制到剪贴板。

## 失败与恢复

| 情况 | 表现 |
| --- | --- |
| 设备没有系统语音识别能力 | “此设备不支持系统语音识别。” |
| 未授权麦克风 | “未获得麦克风权限，请在系统设置中允许 Tinybot 使用麦克风。”，并保留“允许麦克风”入口 |
| 识别引擎返回权限类错误码 | 与未授权相同的提示 |
| 其他引擎错误 | “系统语音识别失败（错误码），请确认设备支持此功能后重试。” |
| 准备或结束阶段超时 | 明确提示超时，释放引擎 |

- 迟到的回调通过会话标识过滤：取消后到达的启动回调不会开始录音，已创建的引擎立即关闭。
- 识别中途失败会把已经识别到的文字合并进草稿并回到文字输入，不会自动发送；合并失败时改为提示“复制识别文字”。
- 切到后台会结束听写并释放引擎；回到前台不会自动继续。
- 组件卸载、切换会话时同样释放引擎，不会在后台保留录音；切换会话会丢弃本次尚未应用的转写。

## 朗读回答

助手回答生成结束后，可从消息的更多菜单或长按菜单选择“朗读回答”。朗读期间输入框上方显示状态与“停止朗读”，同一菜单也可停止。

- 使用系统文本转语音，不需要模型 API Key，不经过配置的模型服务。
- 正文中的 Markdown 会转为文字，跳过代码块、图片地址与交互 UI 数据；长回答分段播放。
- 包含汉字时使用中文音色，否则使用英文音色；英文音色需设备已安装，缺失或引擎失败时显示系统错误，不自动下载。
- 一次只朗读一条回答，开始另一条会先停止前一条；开始朗读会先结束正在进行的听写，草稿保持原样。
- 切换会话、进入后台或组件卸载都会停止朗读。
- 失败提示包括“此设备不支持系统朗读。”“这条回答没有可朗读的正文。”“朗读失败（错误码）：原因”和 15 秒无响应的超时提示。

## 桌面快捷入口

长按桌面 Tinybot 图标，可选择“新对话”或“语音输入”。两者都会先保存原草稿，再创建一个不属于任何项目的新对话。

- “新对话”进入空白聊天；“语音输入”在该新对话中直接切换到按住说话模式，仍需按住并松手才会录制，文字不会自动发送。
- 冷启动会等待本地会话加载完成再处理快捷入口。
- 任务进行中、正在接收分享或草稿保存失败时提示“请先完成当前操作或保存，再使用快捷入口。”，不打断当前任务。

## 系统接入边界

- 识别与朗读都由系统能力提供：识别依赖 Core Speech Kit 的语音识别引擎，朗读依赖系统文本转语音引擎。缺少对应 `SystemCapability` 时明确提示不可用，不做降级替代。
- 应用只使用前台麦克风权限，不录制系统声音、不读取其他应用的音频。
- 应用不保存音频、不生成录音文件，也不把音频上传到模型服务；模型只接收转写后的文字。
- 识别语种跟随系统识别服务的中文能力，不提供应用内语种选择；英文朗读音色由设备已安装的音色决定。
