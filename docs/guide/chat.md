# 对话与消息

这页覆盖一条会话从输入到归档的全部操作：怎么发、怎么排队、怎么停、怎么改和分支，以及引用、附件、草稿、搜索与记忆各自的行为边界。

## 三种提交方式

输入框在任务运行期间保持可用，同一个草稿有三种去向：

| 方式 | 入口 | 生效时机 |
| --- | --- | --- |
| 发送 | 发送按钮 | 当前没有任务时立即开始新一轮 |
| 追加（steering） | 生成中出现的“追加” | 等当前模型响应与整批工具调用完成后，在下一次模型请求前按顺序接收 |
| 排队（follow-up） | 生成中的“排队”，或长按发送按钮选“加入队列” | 当前任务成功结束并保存后，自动逐项开始 |

追加不打断、不回滚正在执行的工具；即使模型本来准备结束回答，有待接收指令时也会继续响应。运行时用 `/skill:名称` 切换 Skill 必须走排队，因为一次运行内工具与 Skills 固定。

## 待发送队列

队列由会话服务统一调度，落盘与恢复方式见[会话与持久化](/internals/session)。

| 规则 | 取值或行为 |
| --- | --- |
| 保存范围 | 按会话分别保存，切换会话各自独立 |
| 条数上限 | 每段会话最多 20 条 |
| 单条长度 | 1 至 24000 字符 |
| 顺序 | 追加优先于排队，两类内部都按加入顺序 |
| 附件 | 加入队列时一并保存当前附件，执行该项时发送 |
| 引用 | 不支持排队；有会话引用时先移除引用或等任务结束 |
| `/compact` | 不能排队，需在任务结束后单独发送 |
| 停止或失败 | 停止、模型错误、保存错误都会暂停后续任务，未开始的指令保留 |
| 重启 | 队列永远以暂停状态恢复，点“继续队列”才继续 |

队列项可以展开、收起、移除，也可以“撤回编辑”：内容回到输入框，附件一并恢复。当前已有草稿时撤回会被拒绝，需要先处理草稿。执行队列不会清空你另行输入的草稿，也不会让暂停的队列自行恢复——手动发送新消息不等于继续队列。

## 停止

点停止会取消当前网络请求、阻止后续工具执行，并暂停队列。已经提交的文件写入保留，不自动回滚；本轮已完成的工具结果与已发布预览继续可见。这条回答标记为“已停止”，不会伪装成完整回答，未完成的正文也不会进入下一轮上下文。

## 改写、重新生成与分支

三种操作都会新建会话，原会话保留在列表里，并在标题后加上“· 分支”。

| 操作 | 位置 | 结果 |
| --- | --- | --- |
| 改写（编辑重发） | 用户消息的操作栏 | 从该消息创建分支，内容、附件、引用回到新分支草稿，等待你修改后发送 |
| 重新生成 | 助手回答的操作栏（“重新生成（保留原回答）”） | 从该回答的上一条用户消息创建分支并立即再次发送 |
| 分支 | 助手回答的操作栏、“创建分支”菜单 | 保留所选助手消息及之前的内容，不自动发送 |

分支的继承与限制：

- 模型选择、推理强度、团队模式、工具选择与 MCP 停用项沿用当前会话；只有改写用户消息时，该消息的正文、附件与引用才进入新分支草稿，其他情况下新分支草稿为空。
- 普通会话的分支使用独立空工作区，历史文件不复制；项目内分支继承项目归属，继续使用同一份当前文件。模型会在上下文里收到相应说明。
- 任务运行中或存在未处理的保存错误时不能分支或重新生成；新分支保存失败就不发起生成。
- “分支关系”面板展示父子关系，可返回来源消息；来源会话被删除后，列表显示“原对话已删除”。

## 引用

### 会话引用

输入 `@` 搜索其他会话标题，或从“+ → 引用其他会话”进入。

- 每条消息最多引用 4 个会话，可预览、可移除，不能引用当前会话，也不能重复引用同一个。
- 携带的是选择当时的文字快照：预览最多 8000 字符，超出时同时保存完整快照。
- 发送后源会话再修改或删除，已保存的引用不变；只能读取被引用过的会话。
- 只引用完整轮次的正文，不含思考、附件和工具记录；老数据没有全文时标记为仅预览。
- 超过预览长度时，模型可用 `read_reference` 按消息 ID 与源会话 ID 分页补读。

### 选段引用

文件面板、附件预览和消息的“选择文本”都能把一段文字放进草稿：

- 消息与附件在独立预览页选择文字，点引用后追加到当前草稿。
- 文件引用会带上路径与大致行号，实际放入草稿的文字最多 4000 字符，并留一句“修改要求：”等待你补充。
- 引用只写入草稿，不自动发送。

助手回答的操作栏末端显示 AI 标记，用户消息不显示该标记。独立成行的 HTTPS Markdown 图片按固定高度展示，点击可全屏查看；加载失败时显示可用浏览器打开的文字卡片，段落和表格内的图片仍显示为链接。

## 附件与图片

每条消息最多 4 个附件，图片、文本、文档与画板共用这个额度：

| 类型 | 上限 | 发送后的形态 |
| --- | --- | --- |
| 图片 | 原图 20 MB、8000 万像素 | 缩至最长边 1600 px、JPEG 质量 85、结果不超过 4 MB；需要视觉模型 |
| 文本 | 无 64 KiB 限制 | 完整保存在会话数据中；小文本直接进消息，大文本按需分段读取 |
| PDF / Office | 原文件 8 MB | 提取文字保存为文本副本；PDF 最多 100 页，超长明确截断 |
| 画板 | 受设备手写能力限制 | 导出白底 JPEG 加入草稿 |

附件可以单独发送而不写文字。附件预览里也能选段引用。文件从哪里来、存在哪里见[文件与工作区](/guide/files)。

## 消息操作栏

每条消息下方是一排紧凑图标，同一项只出现一次，长按正文仍可打开系统文字菜单。

| 操作 | 用户消息 | 助手回答 | 可用条件 |
| --- | --- | --- | --- |
| 复制 | 有正文时 | 有正文时 | 始终可用 |
| 选择文本 | 有正文时 | 有正文时 | 始终可用；在独立面板里选词、复制、引用 |
| 朗读回答 | — | 有正文时 | 回答不在生成中；朗读中图标变为停止 |
| 改写 | 有 | — | 任务结束且没有保存错误 |
| 重新生成 | — | 有 | 任务结束且没有保存错误 |
| 分支 | — | 有 | 任务结束且没有保存错误 |
| 提炼为记忆 | — | 有正文时 | 任务结束且没有保存错误 |

复制走系统剪贴板，失败时提示改用长按选择。朗读使用系统语音合成，再次点击同一按钮即可停止。

## 一次回答里能看到什么

| 区块 | 内容 |
| --- | --- |
| 状态线 | 最外层的整轮状态，完成后收束成耗时摘要；手动展开的过程不会被自动收起 |
| 思考 | 单行预览，展开看全文；较长的思考可继续加载 |
| 工具回执 | 工具名、参数、结果与差异；失败保留红色提示与错误码 |
| 正文 | Markdown 渲染，代码块可复制，表格与代码横向滚动 |
| 附加卡片 | 交互预览、图表、计划、表单、团队卡片与文件交付 |
| 本轮修改 | 本轮确实写过文件时出现在回答末尾 |

## 发送失败与拒绝

发送前会逐项检查，任何一项不满足都不会静默丢弃内容：

1. 未登录华为账号：打开“华为账号”页，草稿保留。
2. 会话已归档：提示先恢复对话。
3. 存在未处理的保存错误：输入区上方出现错误条与“重试保存”，发送按钮不可用。
4. 内容为空：文字、附件、引用至少有一项。
5. 当前任务尚未结束且不允许排队：例如带会话引用或 `/compact`，提示稍后发送。

## 草稿与输入状态

- 草稿按会话保存，切换会话、退出页面、重启都会保留；会话列表里带草稿的会话显示“草稿”标记。
- 草稿先进入内存并即时反映到界面，再走会话保存队列落盘；保存失败时输入区上方出现错误条与“重试保存”。
- 单条草稿最多 24000 字符，超过上限的输入不会被写入。
- 草稿、附件、引用在发送前都不计入模型上下文；发送时一次性成为消息的一部分。
- 运行中输入的新内容不会覆盖队列中已保存的指令，也不会被队列执行清空。

## 搜索、置顶、归档与删除

| 操作 | 行为 |
| --- | --- |
| 搜索 | 匹配会话标题、消息正文、追加指令与待发送输入；消息正文命中时列表显示匹配摘要，打开后定位到该消息并高亮，搜索期间自动展开匹配分组 |
| 置顶 | 在各分组内部优先排序，不影响归属 |
| 归档 | 会话移入“已归档”分段；打开时显示“这段对话已归档”提示条，可一键恢复；归档当前会话会切换活动会话 |
| 改名 | 1 至 80 字符；手动改名后自动标题不再覆盖 |
| 删除 | 二次确认，提示工作区文件会保留；支持多选批量删除与批量归档 |

删除会话只删除会话记录，不删除它在 `workspace/` 下的目录；需要清理文件请到文件面板手动删除。归档不是只读锁：恢复后即可继续。

## 记忆

| 方式 | 触发 | 规则 |
| --- | --- | --- |
| 手动提炼 | 消息菜单“提炼为记忆…” | 调用记忆模型（未指定则用当前模型）产出最多 5 条、每条最多 200 字符的候选；长消息只取前 12000 字符；助手回答会结合前一条用户消息判断依据 |
| 自动提取 | “设置 → 自动提取长期记忆”（默认开启） | 任务成功后额外调用指定模型，只从本轮用户消息提取事实，过滤已存在的相同条目，并保存来源会话与消息 |

候选必须逐条确认后才保存，默认只用于当前会话；取消、失败或没有新信息都不写入原文。注入上下文时按最近更新时间排序，总预算 16000 字符，超出会提示模型没有加载全部条目。手动记忆不会被自动提取覆盖，去重目前是规范化文本匹配。

记忆与模板的完整管理与上限见[设置、外观与用量](/guide/settings)。

## 自动标题

会话的第一条消息发送后，应用在后台用本轮实际模型生成标题：最多 28 字符，跟随输入语言，不携带历史与工具，不阻塞回答。生成失败时保留首句摘要；你手动改名后，晚到的结果不会覆盖，已归档或已删除的会话也不会被改写。

## 团队模式

输入 `/team` 或从“+ → Agent 团队”开启后，同一轮可以由多个员工并行处理，团队卡片与交接记录挂在发起它的回答下。是否开启、成员与并发上限见[团队协作](/guide/teams)。

## 上下文压缩

输入 `/compact` 并发送，或从输入框的上下文面板点“压缩较早对话”，会用当前模型为较早消息生成摘要。完整记录仍保留在本机，只是发送给模型时用摘要替换；面板里可以查看摘要内容。压缩失败时命令留在草稿中，压缩期间新输入的内容不会被清空。

自动压缩默认开启：估算输入超过剩余预算时触发，保留最近一段完整历史。预算推导与触发阈值见[模型服务与上下文](/guide/models)。
