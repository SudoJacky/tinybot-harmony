Tinybot v1.2.2 · 发布准备说明
更新日期：2026-10-29

一、版本与产物

本版产物需从 1.2.2 源码重新构建；历史版本产物不作为本版提交。

包名：com.sudojacky.tinybot
版本：1.2.2，versionCode=1002002
设备：phone、tablet，最低 HarmonyOS 6.0.0（API 20），目标 API 26；同一包覆盖两套系统
发布包：release，app.debug=false，仅 arm64-v8a
模拟器：使用单独构建的调试包，包含 x86_64；不随正式发布包分发。

两套系统的能力差异（需在发布说明和商店文案中保持一致）：
- 沉浸光感材质需要 API 26 及设备支持；API 20 或不支持该材质的设备使用普通界面。
- PDF 文字提取依赖系统 PDFKit；API 20 未提供该模块，仍可保留 PDF 原件，读取时明确提示不支持文字提取，不生成空白文本。
- 携带凭据的网络请求在 API 20 上同样不跟随重定向。

1.2.2 新增并行会话、本地小程序与数据保存、后台完成通知，支持系统文档分享和图片、文件拖入聊天，每条消息最多 10 个附件。小程序默认关闭，可在实验室开启；支持重命名、导出、恢复上一版及移除后恢复。优化收藏列表、全屏预览、搜索设置与工具响应，新增 QQ 社区入口和评价邀请。模型 API Key 随华为账号加密备份，同账号换设备可恢复。修复旧小程序清单兼容、恢复后模型服务未注册、后台预览误超时，以及平板侧栏空白、标题遮挡和菜单背景缺失等问题。验证记录和外部待办分别见 CLOUD-TEST.txt、RELEASE-GAPS.txt。

运行 scripts/prepare-distribution.ps1 后生成独立目录及 ZIP：
packages/Tinybot-1.2.2-1002002-release-UNSIGNED.app：待云签名的完整发布包。
packages/Tinybot-1.2.2-1002002-release-UNSIGNED.hap：同一 APP 内的 entry 模块。
symbols/app-symbol.zip：ArkTS 符号表。
symbols/native/arm64-v8a/：与发布包 Build ID 一致的未裁剪原生沙箱库。
assets/tinybot-icon.png：工程使用的图标。
screenshots/：仅附带本机已准备的商店截图；拍摄版本与内容需单独核对，历史图不作为本版验证结果。
licenses/：工程 Apache-2.0 和随包第三方许可证。
policies/：随包用户协议原文；隐私政策使用华为托管。
RELEASE-NOTES.txt、STORE-LISTING.txt、CLOUD-TEST.txt、RELEASE-GAPS.txt：版本文案与验证资料。
PRIVACY-DRAFT.txt：指向应用实际使用的政策文件，替代旧版独立草稿。
ACL-APPLICATION.txt（如本地提供）：FILE_ACCESS_PERSIST 权限申请草稿，版本与平台资料需提交前核对。
package-info.json、SHA256SUMS.txt：从实际包读取的元数据、文件大小、原生 Build ID 和 SHA-256。

二、本地生成

在项目根目录使用 PowerShell 7 运行（避免 Windows PowerShell 5.1 的 UTF-8 脚本编码问题）：
pwsh -ExecutionPolicy Bypass -File scripts\prepare-distribution.ps1 -StudioRoot "C:\Program Files\Huawei\DevEco Studio"

脚本先检查 ArkTS，再构建 Release；需确认 APP 已使用 assembleApp 从本轮 Release 产物组装，验证版本、debug 标志、包内容、arm64 沙箱库和符号 Build ID，最后生成交付目录及 ZIP。已有输出不覆盖；可使用 -OutputDirectory 指定新目录。
-SkipBuild 仅打包既有产物，仍校验包结构和版本，但不能证明包含最新代码。

三、签名与上传

本地自动签名使用调试 Profile。Release 编译不等于发布签名；交付包中的 UNSIGNED 文件需要正式签名才能安装或发布。

在 DevEco Studio 的 Build > Upload Product 中选择工程原始产物：
build\outputs\default\tinybot-harmony-default-unsigned.app
关联现有包名 com.sudojacky.tinybot，核对 1.2.2 / 1002002，使用对应发布证书或云管理签名，附带本版符号表。最终签名包的哈希会变化，以最终文件重新记录。

此步骤需在实际平台完成；本地准备不包含创建应用、申请证书、上传、云测试或审核结果。控制台字段以当前平台为准。如版本号已使用，增加 versionCode 后重新构建。

四、资料与回归

应用内保留用户协议离线阅读；隐私政策使用华为托管和系统签署流程。公开政策地址、商店截图、审核体验配置等平台资料见 RELEASE-GAPS.txt。
使用相同签名从旧版覆盖升级，检查会话、模型配置、草稿和工作区；不卸载或清空用户数据。只在干净的独立测试环境检查全新安装。
