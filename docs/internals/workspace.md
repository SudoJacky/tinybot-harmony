# 工作区与文件

会话默认读写应用私有目录下的工作区（workspace）；项目还可明确授权系统共享文件夹。这页说明目录如何布局、项目为什么共享同一目录、路径与写入如何校验、修改基线怎样恢复，以及导入导出、附件与小程序各自落在哪里。项目与分支的用户侧行为见[项目与共享工作区](/guide/projects)，日常操作见[文件与工作区](/guide/files)。

## 应用级布局

工作区根目录在运行时由 `WorkspaceStore` 拼成 `ApplicationContext.filesDir/workspace`。普通会话使用会话 ID，项目会话使用项目的 `workspaceId`；两者都是根目录下的一级子目录，没有额外存储授权。

```text
<ApplicationContext.filesDir>/
├─ workspace/
│  ├─ <会话 ID>/
│  │  ├─ 笔记-1008-1420.md
│  │  ├─ 任务结果/<消息 ID>.md
│  │  ├─ attachments/<附件 ID>/<文件名>   文本与文档原件
│  │  ├─ mini-apps/<appId>/
│  │  │  ├─ app.json                     页面与元数据
│  │  │  └─ data.json                    用户数据
│  │  ├─ .tinybot-review/
│  │  │  └─ <encodeURIComponent(路径)>.json
│  │  └─ .tinybot-<uuid>.tmp
│  └─ <workspaceId>/              项目内所有会话共享
├─ attachments/
│  └─ <附件 ID>.jpg               图片附件
└─ 会话、用量、诊断等应用数据
```

会话 ID 与项目 `workspaceId` 都必须匹配 `^[A-Za-z0-9_-]{1,128}$`，在触碰文件系统之前完成校验。项目数据还要求 `workspaceId` 全局唯一，且不能与任何普通会话 ID 冲突。

`.tinybot-` 前缀是保留命名空间：目录列表会过滤这类名字，工具路径也不接受以它开头的段。临时文件与目标文件位于同一目录，重命名不跨目录。

## 项目共享目录

项目的 `sharedFolders` 经 `SharedFolders.ets` 校验；`ProjectFolderAccess.ets` 负责保存系统读写授权、进程启动后的激活和移除后的撤销。`NativeWorkspaceFiles` 把授权目录挂载到虚拟的 `shared/<名称>/`，每层路径都拒绝符号链接。指向同一 URI 的不同项目挂载共用文件修改队列，避免别名绕过内容版本校验。

共享目录先将系统选择器 URI 转为路径以打开或创建目标，再以文件描述符直接写入，不依赖公共目录的重命名能力。URI 打开作为已有文件的兼容方式；若两种方式都失败，保留首个路径错误码及 URI 错误，不用后者掩盖前者。兼容应用数据下的 Obsidian 目录在真机上允许以转换后的路径创建和写入，但拒绝重命名，直接用 URI 新建文件也会失败。共享写入不是原子操作：写前必须在应用私有工作区持久保存原始备份；备份失败则不写入目标内容。写入后按 UTF-8 字节长度截断、`fsync`、关闭，任何失败都返回错误，保留备份供恢复或导出。

项目会话的路径解析顺序是：`thread.projectId` → 找到项目 → 使用 `project.workspaceId`。同一项目的所有会话因此读写同一批文件，但对话历史、附件、模型与 MCP 设置仍各自归属。

- 项目目录必须已存在。`requireWorkspace()` 检查根目录与项目目录，任一缺失就报“项目工作区不存在，请从备份恢复”，不会自动补建空目录，避免把丢失误当成新项目。
- 普通会话在新建与启动时会补建自己的目录；已有会话切换回来沿用同一目录。
- 删除会话保留工作区文件；卸载应用或清除应用数据才会清除这些文件。首版不提供项目移动或删除。
- 项目说明（最多 16000 字符）与共享工作区提示由 `projectContext()` 加入系统提示词，同时明确“历史回执不是当前文件快照”。
- 分支在项目内继承项目归属与当前文件；普通聊天分支使用新的独立空工作区，不复制历史文件。

## 路径解析与校验

工具只接受工作区相对路径。`workspaceRelativePath()` 先做语法检查，`NativeWorkspaceFiles.resolve()` 再逐段落地：

| 阶段 | 检查 |
| --- | --- |
| 语法 | 非空、≤1024 字符；禁止反斜杠、冒号与控制字符；≤16 段；无空段、`.`、`..`；非 `.tinybot-` 开头 |
| 根 | 工作区根必须是绝对路径且不以斜杠结尾；根与其父目录必须是真实目录 |
| 逐段 | 对每一段 `lstat`；任一段是符号链接即拒绝；中间段必须是目录 |
| 目标 | 读取与写入都用 `NOFOLLOW` 打开；已存在的目标必须是普通文件 |
| 创建 | 写入时只为缺失的中间父目录执行 `mkdir`，不会替换已存在的段 |

列表、检索与查找允许根路径 `.`；读写与编辑必须给出具体文件路径。`checkedPath()` 供 `present_files` 与图片预览使用，额外要求目标是普通文件而非目录或符号链接。完整规则与拒绝行为见[审批、权限与沙箱](/internals/permissions)。

## 文本读写与原子替换

读取按路径分派：`.pdf`、`.docx`、`.xlsx`、`.pptx` 先交给 `DocumentFiles`/`DocumentText` 提取文字（PDF 使用 PDFKit，API 20 无模块时明确失败），其余按 UTF-8 严格解码，遇到 NUL 字符即判定不是文本文件。提取后的文字再用 `textPage()` 分页：

| 参数 | 默认 | 边界 |
| --- | --- | --- |
| `offset` | 1 | 必须为正整数，不能超过总行数 |
| `limit` | 2000 | 受单页 2000 行上限约束 |
| `column` | 1 | 1 起始的 UTF-16 位置，不能落在代理对中间 |
| 单页字节 | 50 KiB | 超限即截断，返回 `nextOffset`/`nextColumn` |

分页会计入换行符的字节，保证连续读取的片段拼接后与原文一致；超长单行也能用 `nextColumn` 继续。返回结果带 `totalLines`、`truncated` 与接续游标，界面按同一份数据展示。

写入与编辑共用一条路径：

1. 在共享队列中按绝对路径串行，同一文件不会并发改写，不同文件可并行。
2. 解析路径，确认目标不是目录或符号链接。
3. 读取原文并计算 SHA-256（Base64）版本；调用方传入的版本不一致时以 `FS_STALE_VERSION` 失败。
4. 校验编辑：所有 `oldText` 针对同一份原文，必须唯一、不重叠，全部通过后才一次写入。
5. 应用私有工作区在目标目录创建 `.tinybot-<uuid>.tmp`，分块写满、`fsync`，再重命名覆盖目标；共享目录先持久保存备份，以不截断的读写模式打开目标并再次核对原文，再直接写入、按字节长度截断、`fsync`、关闭。不在公共目录创建临时文件。
6. 返回 `{path, bytes, written, before, after, created, version}`，其中前后文本只用于本地差异与界面展示。

写前版本守卫分三种：`version: null` 表示“只能新建”，目标已存在就要求先读取；给出具体版本表示“基于这次读取修改”；省略守卫保留给用户主动操作。编辑前必须在本轮成功读取过该文件，搜索与内部读取不授予修改资格。该队列只覆盖应用内的适配器实例，不锁定其他进程。

## 文件变更基线与恢复

每次写入前，存储层会把“首次修改前”的内容存成基线，路径为 `.tinybot-review/<encodeURIComponent(路径)>.json`：

```json
{ "path": "notes/a.md", "existed": true, "content": "修改前的完整文本" }
```

- 基线只在没有既有基线时创建，因此同一文件连续多次修改共享同一份“原始版本”。
- 共享文件也使用此机制：文件名为 `shared-<URI的SHA-256摘要>.json`，额外记录 `sourceUri`。共享目录改名不丢备份，同名挂载换到其他 URI 时也不会误用旧备份。备份保存在项目的私有工作区，不写入外部目录。
- 基线写入同样走临时文件、`fsync` 与重命名。
- 文件打开后直接显示当前内容，没有差异审阅或“保留修改”确认。有旧内容备份时，“更多操作”菜单提供恢复和导出。
- “恢复”先比较当前内容与界面持有的原文，不一致就拒绝并要求重新打开，避免覆盖期间的其他改动；成功后删除对应基线。新建文件不提供撤销式删除选择，普通删除功能独立存在。
- 项目工作区的基线包含各会话的累计修改，恢复对话框会明确提示可能影响其他会话；聊天里的“本轮修改”仍只描述该轮历史差异。
- 共享文件失败提示说明可能留下部分内容，菜单允许主动导出修改前备份；即使当前内容无法解码预览，仍可导出已保存的备份。恢复共享文件使用同一直接写入方式，失败时不删除备份。

基线属于本地审阅元数据，不进入模型上下文。工具回执另带当次 `fileDiff` 与本轮 `turnFileChange`，同样只用于界面。

## 导入与导出

文件页直接操作用户可见的工作区：

| 操作 | 行为 |
| --- | --- |
| 导入文件 | 系统选择器一次最多 5 个；接受 `.txt` `.md` `.csv` `.tsv` `.json` `.log` `.pdf` `.docx` `.xlsx` `.pptx` |
| 文档处理 | PDF 与 Office 文档按原字节复制，读取或预览时再提取文本；API 20 无 PDFKit 模块时读取明确失败，原件仍保留 |
| 命名 | 去掉路径分隔符与控制字符，截到 80 字符；重名追加 ` (2)` 等序号 |
| 新建笔记 | 生成 `笔记-MMDD-HHmm.md` 空文件并进入编辑 |
| 编辑保存 | 私有工作区原子替换；共享目录先备份再直接写入；未保存退出需确认 |
| 分享 | 先复制到缓存目录并限制在 20 MiB 内，再交给系统分享；之后的源文件改动不影响已分享副本 |
| 导出 | 系统保存选择器写入指定位置，同样限制 20 MiB |
| 删除 | 二次确认后删除；不可恢复 |
| 引用 | 文本选段或前 4000 字符可插入当前会话草稿，标注文件与行号附近 |

列表每页最多 200 项，目录在前、文件在后，各自按名称排序；超过一页时提示“仅显示前 200 项”。符号链接条目会以链接图标显示但不可打开。

## 附件存储

聊天附件与工作区文件分开保存：图片在 `ApplicationContext.filesDir/attachments`，文本与文档原件随消息绑定后复制到工作区的 `attachments/<附件 ID>/<文件名>`。

| 项目 | 限制 |
| --- | --- |
| 每条消息附件数 | 10 |
| 原图 | 最多 20 MB、8000 万像素 |
| 文档 | 无应用级大小上限；按原字节复制，读取时按需提取 |
| 图片落盘 | 最长边缩到 1600 px，JPEG 质量 85，结果不超过 4 MB |
| 文本与文档 | 保留原文件与文件名；模型按工作区路径读取 |
| 模型请求 | 图片转 Base64 data URL；文本与文档以附件上下文（路径与说明）拼进消息 |

附件只保存副本，不持有外部目录的持续授权。拖入与系统分享进入应用的内容同样经 `Attachments.import()` 落盘，一次最多 10 项，分享文本最多 24000 字符。

## 小程序存储

`mini-apps/` 保存本地小程序的页面与用户数据，路径为 `workspace/<workspaceId>/mini-apps/<appId>/app.json` 与由清单指定名称的数据文件（v1 固定为 `data.json`）：

- 页面与元数据在 `app.json`；v1 记录当前页与上一版页面，v2 记录正式数据文件、版本历史与采用记录。用户数据独立存放，更新或恢复页面不会改写它。
- 页面只接受单页 `.js`、`.html` 或 `.svg`，发布前用只读数据快照做启动校验；启动脚本不能写入数据。
- 小程序数据通过 `tinybot.storage.load()` / `save(value, revision)` 读写，带版本守卫；版本过期时保存失败，页面必须重新加载并对齐。
- 移除只归档；归档后“永久删除”才删除整个 `mini-apps/<appId>`。原会话删除后目录仍保留，备份会带走这些保留工作区。
- 小程序集合跨会话列出所有工作区的小程序，按最近打开或更新时间排序；工作区来源显示项目名、会话标题或“保留的工作区”。
