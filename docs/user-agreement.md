这些产品多为自营模型或账号平台，Tinybot 则是个人开发者提供的开源客户端，不能直接套用其训练许可、封号、订阅或专属争议管辖条款。

## 条款依据与功能核对

- [《民法典》](https://www.court.gov.cn/zixun/xiangqing/233181.html)第496—498、506条和[《消费者权益保护法》](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_0a323e046fba43f0b6e9e977f1e8d5fc.html)第26条：重点条款加粗，保留法定责任和消费者权利，不写“全部免责”“最终解释权”或任意单方变更。
- [《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)第8、10条：描述目前的助手身份、聊天提示及对外发布时的声明和标识要求，不承诺已经实现文件水印或隐式标识，也不将提供方的法定义务全部转给用户。
- 主体与邮箱沿用已发布的隐私政策。功能、辅助请求、第三方费用、工具确认、备份凭据边界和 Apache 2.0 许可按当前代码核对。
- 当前没有 Tinybot 账号、会员订阅或应用内购买；争议处理采用法定管辖，不编造开发者地址或强制专属法院。

## 页面与发布边界

“设置 → 关于 Tinybot → 用户协议”打开 `support/terms` 原生子页。`LegalDocumentPanel` 与隐私政策共用阅读组件，各自加载独立的本地 Markdown 资源，支持主题、滚动和复制；资源异常显示实际错误。

本次实现协议文本与阅读入口，不增加同意按钮或生成同意记录。版本日期为 2026年10月18日，不将该日期写成已经对所有用户生效的时间。首次使用告知、有效同意及依法需要的单独授权属于独立流程，不能仅凭该阅读页宣称已经完成。

本文本为结合现有功能起草的版本，尚未经过法律专业人士审阅；正式发布时需核对适用主体、实际功能、发布安排及法定义务。应用内正文不混入调研资料或评审说明。
