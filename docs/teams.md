# 聊天中的团队协作

[文档索引](README.md) · [项目首页](../README.md)

## 使用入口

对齐桌面端 Chat coordinator 流程：在聊天输入框输入 `/team` 选择命令，或直接发送 `/team 目标`（也兼容 `@team`）。模式保存在当前会话，后续对话继续可用；输入框上方可关闭。单独发送命令只启用模式，不调用模型。

## 招募、调度与交接

主 Agent 根据需要自由招募、边工作边追加员工和任务，并承担最终整合；不再要求手动配置角色、生成独立计划或点击确认执行。员工继承主 Agent 的模型和会话工作区，使用独立执行记录，不能继续招募或向用户发布最终图表。每个团队支持 1–8 位员工、最多 32 个无环依赖任务，最多 4 个任务并行；同一员工串行处理任务。主 Agent 与员工的工作区工具和确认对话框共用串行通道，避免同时写入或弹出确认。

模型工具使用兼容服务的下划线名称：`team_recruit`、`team_wait`、`team_inspect`、`team_read_result`、`team_control` 和 `team_resume`，对应桌面同名点号工具。招募返回后主 Agent 可以继续自己的工作；等待按提交事件唤醒，不返回空超时或额外发起模型轮次。游标分页避免重复消费结果，主 Agent 提前结束时会等待员工交接并在同一轮继续整合。

员工必须通过 `team_complete_task` 交接摘要、未解决事项和实际产物路径，成功落盘后才对主 Agent 可见。支持 research / execution / review 权限范围：research 使用文件与网页工具；review 只读；execution 继承已启用工作工具。员工可用 `team_list_messages` 和 `team_read_message` 读取本团队交接。交接文本产物保留原始内容，主 Agent 读取时核对当前文件；文件变化会报错，不把新版冒充旧结果。交接会完整读取并核验各页；单份文本产物最多 65536 字符，每次交接最多 8 份文件、总计 128000 字符。

## 停止与恢复

停止聊天会取消本轮启动的所有员工并等待收尾。暂停停止派发并等待正在执行的员工完成；失败、中断或取消任务必须明确重试再继续，不自动重放文件或远程副作用。重启保留模式、团队、尝试和交接，运行中的工作标为中断。团队工具只能访问本聊天的团队；原有手动团队记录以聊天末尾的“历史团队”卡片保留只读查看。手机系统终止应用后不承诺继续运行。

## 界面、用量与备份

团队功能全部收在聊天中，不再保留独立团队页面及菜单入口。团队卡片默认展示成员和完成进度；原地展开后可查看任务、交接摘要、未解决事项、产物路径和用量，任务详情中可继续展开执行记录。最终回答始终在主聊天中，文件从本会话工作区查看。团队用量展示员工已报告 Token；主 Agent 请求在原聊天和全局账本中，未报告用量标为未知。备份包含团队记录和文本交接，恢复时重映射所属消息、团队及模型引用。

自动化检查和已有设备验证记录见[开发与验证](development.md)。
