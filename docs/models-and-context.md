# 模型服务、上下文与限制

[文档索引](README.md) · [项目首页](../README.md)

## 内置模型服务

| 服务 | 默认服务地址 | 预设模型（首项为默认） |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash`、`deepseek-v4-pro` |
| DashScope / 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`、`qwen-max`、`qwen-turbo` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1` |
| Z.ai / 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3`、`glm-5.3-flash`、`glm-5.2` |
| Ollama | 手动填写手机可访问的服务器地址 | 手动填写服务器上已安装、支持工具调用的模型 |
| 自定义兼容服务 | 手动填写 HTTPS 地址 | 手动填写 |

预设只是填写入口，不代表账号已经开通相应模型。打开设置不会覆盖现有配置；选择内置服务会应用它的默认值，自定义兼容服务保留当前草稿。可保存多份服务配置，每份分别管理协议、地址、密钥、模型列表和启停状态。每段对话独立选择模型，也可设置新会话默认模型；删除或停用服务后会提示重新选择，不自动切换其他服务。同一服务基础地址下切换协议或修改名称、模型、上下文窗口等设置会保留原密钥；更换域名、端口、HTTP/HTTPS 或服务基础路径时需要重新填写密钥。

Ollama 通过其 [OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility) 连接服务器，不在手机内运行模型。填写例如 `http://192.168.1.100:11434/v1` 的实际服务器地址，确认手机能访问该服务器；`127.0.0.1` 指向手机本身。选择 Ollama 时清空云端地址/模型并默认启用“无需 API Key”，使用受保护的代理时可关闭该开关并填写密钥。服务配置允许显式填写 HTTP 以连接本地模型；云端服务建议保留 HTTPS。无需增加系统权限。

GLM 等模型返回的 `reasoning_content` 会独立组装，随工具步骤保存，并由支持该字段的适配器回传；不会混入最终回答。OpenAI 的请求不携带这个厂商扩展字段。[智谱文档](https://docs.bigmodel.cn/cn/guide/capabilities/thinking)明确说明 GLM 5.3 不支持关闭思考，因此本实现保留协议上下文，不通过强行禁用思考绕过多轮工具调用。

内置云端服务的 API Key 区域下方提供“获取 API Key”链接，在系统浏览器中打开对应的官方控制台。DeepSeek、DashScope、OpenAI 和智谱的地址与 Tinybot Desktop 对齐，OpenAI Responses 共用 OpenAI 的入口，Anthropic 使用 [Claude 官方密钥页面](https://platform.claude.com/settings/keys)。链接来自预设元数据 `apiKeyUrl`，不随服务改名改变；自定义服务、Ollama 和启用“无需 API Key”的配置不显示该入口。

- API Key 使用 Asset Store Kit 保存，并禁止跨设备同步；更换服务商或服务地址时需重新填写密钥。旧设置迁移为自定义兼容服务，保留已有地址、模型和密钥。

## 上下文预算与用量

上下文预算按「单模型覆盖 → 服务覆盖 → 模型默认值」解析。服务高级设置和助手的模型能力设置均可留空恢复自动值；通用默认 **200000 tokens**，`deepseek-flash`、`deepseek-v4-flash`、`deepseek-v4-flash-vision-exp`、`deepseek-v4-pro`、`glm-5.3`、`glm-5.3-flash` 默认 **1000000 tokens**。这是客户端的预算，不会改变服务器实际支持的窗口。已有显式数值（包括旧配置中的 32768）保留，避免覆盖手动配置；清空服务与单模型的覆盖值后使用新默认值。模型规则集中在 `ConversationContext.ets`，适用于同名模型的自定义代理。

正常对话不再主动设置 Chat Completions 的 `max_tokens` 或 Responses 的 `max_output_tokens`，由服务决定默认输出长度。[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create) 要求 `max_tokens`，目前协议层保留 4096 兜底。压缩和记忆提取属于独立的短输出任务，仍使用专门预算。输入预留与摘要输出预算分离，均不作为正常回复输出上限。

点击输入框的上下文圆圈，可查看当前预计占用、剩余容量，以及系统指令、工具定义、用户输入、助手内容、工具结果、历史摘要、附件与引用、消息格式开销的分类估算。分类可展开到指令段、具体工具或保留消息所属的轮次/步骤；草稿与待发送附件另计。分类基于实际请求投影，已压缩历史和仅保存在本地的编排子回执不会重复计入，大工具结果只计发送的预览。分类合计是启发式估算，不强制等于服务端用量校准的占用。生成中展示最近一次请求的内容；空闲时重新估算当前保留内容。

同一面板独立展示当前会话所有聊天轮次累计的模型请求次数、实际输入、输出、缓存与推理用量；每轮消息下方仍展示该轮统计。累计基于当前会话保存的聊天记录，不受消息列表分页或上下文压缩影响，切换会话后随之切换。未报告显示未知，部分上报标记“部分”；缓存包含在输入、推理包含在输出，不重复相加。标题、记忆整理和团队员工的独立请求不计入此处的会话累计，完整请求统计仍在设置的 Token 用量中。展开明细仅作展示，不会发起模型请求；原有压缩操作保留。

## 默认值与固定限制

以下列出与模型、上下文及工具使用相关的默认行为和主要固定限制。这里的“固定”指应用没有用户设置入口，并不表示产品上必须禁止修改。

| 项目 | 当前值或行为 | 用户可设置 |
| --- | --- | --- |
| 上下文窗口 | 通用 200k，以上 DeepSeek / GLM 模型 1M；显式范围 8192–2000000 | 是，按服务或单模型覆盖、留空恢复自动 |
| 自动压缩历史 | 默认开启，预留 `min(16384, 窗口 / 2)` tokens，估算输入超过剩余预算时触发 | 可开关；触发阈值固定 |
| 压缩保留近期历史 | `min(20000, 窗口 / 4)` tokens，至少保留最近完整一轮 | 否 |
| 压缩摘要 | 请求最多输出 4096 tokens；摘要最多 32768 字符且估算少于 4096 tokens | 否 |
| 单任务模型调用 | 默认/最大 200 次；最后一次若仍要求工具则停止 | 无界面入口，内部调用方可降至 1–200 |
| 单次模型响应的工具数量 | 最多 8 个；顺序执行 | 否 |
| 工具参数 / 推理内容 | 单工具参数最多 96×1024 字符；单步推理内容最多 1024×1024 字符 | 否 |
| 普通回复输出 token | Chat Completions / Responses 不传；Anthropic 兜底 4096 | 无界面入口 |
| 模型网络请求 | 连接超时 15 秒；首段数据及后续无数据超时 120 秒，每次非空数据重置；无固定总时限 | 否 |
| 模型流式响应体 | 不按累计网络字节中断；各协议单帧/缓冲最多 1 MiB 字符，推理内容与工具参数仍按上述实际内容限制 | 否 |
| 输入 / 待发送队列 | 每条 24000 字符；每段对话最多 20 条待发送输入 | 否 |
| 跨会话引用 | 每条消息最多 4 个；每个引用预览最多 8000 字符，完整快照按需补读 | 否 |
| 工作区文件工具 | UTF-8 文本，无固定单文件大小上限；列表/搜索最多 200 文件，搜索最多 100 匹配，单次读取最多 2000 行 / 50 KiB，可续读 | 上限固定，部分工具可请求更小范围 |
| 代码沙箱 | 同步 JavaScript，2 秒、32 MiB Runtime 分配；代码和 JSON 输入各最多 32 KiB UTF-8 | 否；其余输出限制见[代码沙箱文档](code-sandbox.md) |
| 网页读取 | 联网工具默认开启；最多 30 秒、1 MiB；正文 20000 字符、链接 30 个 | 可开关联网工具；预算固定 |
| MCP | 最多 10 个服务；请求 60 秒、响应 1 MiB；已接受的工具结果完整保存，模型按预算预览并可分页补读 | 可编辑服务及启停；预算固定 |
| 模型发现 | 连接 15 秒、读取 30 秒、响应 1 MiB，最多取 200 个去重模型 ID | 可手动添加模型；发现预算固定 |
| Skills | 最多 20 个、每个 16 个参考文件；单文档 32000 字符，总计 512000 字符 | 可编辑内容及启停；预算固定 |
| 附件 | 每消息 4 个；文本无固定大小上限，小文本直接发送，大文本按需分段读取；Office/PDF 原文档 8 MiB；原图 20 MB、8000 万像素，缩至最长边 1600 px、JPEG 质量 85、结果 4 MB | 否 |
| 长期记忆 | 最多 100 条，每条 2000 字符；注入上下文最多 16000 字符 | 可编辑/删除记忆；预算固定 |
| 记忆提取 | 手动请求输出 1600 tokens，最多 5 条×200 字符；自动请求输出 2000 tokens，最多 5 条×500 字符 | 自动提取默认开启、可关闭；预算固定 |
| 模板 | 最多 100 个；名称 40 字符、正文 12000 字符 | 可编辑内容；上限固定 |
| 团队 | 最多 8 位成员、32 个计划任务 | 可编辑成员/任务；上限固定 |
| 聊天团队并发 | 默认 2，范围 1–4 | 创建团队的工具可传参；范围固定 |
| 备份 | 最多 20 MiB、1000 个工作区文件 | 否 |
| 自动记忆 / 结果归档 / 只读模式 / 自动路由 | 自动记忆默认开启，其余默认关闭 | 是，统一设置 |
| 图片输入 / 请求流式用量 / 推理强度 | 默认允许图片、请求 Chat Completions 流式用量、推理跟随服务默认 | 是，按模型配置；支持的模型还可按会话调整推理强度 |
| temperature / top_p / seed | 应用不主动传递，使用服务默认 | 无界面入口 |

## Tinybot / pi 参数对照

对照本机源码版本（2026-10-04），不是在线模型规格承诺。参考仓库不作修改。

| 项目 | Tinybot 桌面版 | pi | 鸿蒙版取舍 |
| --- | --- | --- | --- |
| 通用上下文 | 128000，已知 DeepSeek / GLM 5.3 模型 1M | 按模型目录解析 | 保留用户要求的 200000 通用值，补齐 Tinybot 的六个 1M 型号 |
| 任务轮数 | 默认 200，用户可配置 | Agent Loop 持续处理工具和追加输入，无该固定 200 轮阈值 | 保留 200 |
| 正常输出 token | 可选，未设置则不传 | simple-options 默认取模型 maxTokens，并按上下文余量收缩 | 遵循用户要求，对 Chat Completions / Responses 不传 |
| 自动压缩 | 默认 90% 触发 | 剩余 16384 tokens 时触发 | 采用 pi 预留值，窗口不足时预留一半；同一预算用于执行轮中的输入检查 |
| 压缩保留内容 | 优先保留用户消息，预算最多 20000 tokens / 消息预算的 25% | 近期约 20000 tokens | 保留近期约 20000 tokens，继续按完整用户/助手及工具组切分 |
| 压缩摘要输出 | 默认 1024 tokens | 常规摘要约预留的 80%，受模型输出上限约束 | 维持独立 4096 预算，本次不移植摘要层级合并和提示词策略 |
| 流式网络超时 | 初始请求及流空闲默认 120 秒，可按服务配置 | HTTP 空闲默认 300 秒，可选 30/60/120/300 秒或关闭 | 采用 120 秒无数据计时，移除旧 180 秒总时限；SDK readTimeout=0，由可重置计时器处理读取超时 |
| 自动重试 | 最多 3 次，限响应流开始之前 | 默认 3 次，基础延迟 2000ms，可配置 | 输出前的临时错误最多重试 2 次（1 秒、2 秒），可取消并保存状态；不完整输出不重试，不重放工具 |
| 工具结果 | 由具体工具决定 | 通用截断默认 2000 行 / 50 KiB | 继续使用工具各自预算；桌面进程/文件权限不直接移植到手机 |

参考位置：Tinybot 的 `src-tauri/src/agent/provider/model-defaults.json`、`catalog.rs`、`completion.rs`、`retry.rs`，`src-tauri/src/agent/runtime/usage.rs`，`src/app-core/settings/agentDefaultsSettings.ts`；pi 的 `packages/coding-agent/src/core/compaction/compaction.ts`、`settings-manager.ts`、`http-dispatcher.ts`、`tools/truncate.ts`，`packages/ai/src/api/simple-options.ts`、`anthropic-messages.ts` 和 `packages/agent/src/agent-loop.ts`。

此处的服务名称和预设描述仓库配置，模型实际可用性以用户账号和服务端为准。
