# 图片生成与编辑

先确定用户想要新图、参考现有图创作，还是修改指定图片。用户只要求写提示词时，交付提示词。用户要求出图时，用 `image_gen`。需求足够清楚就直接做。只有选错目标图或误解硬性要求会明显影响结果时，才向用户确认。

## 从文字生成

- 把用途和主体写在前面，再按需要补充场景、构图、视角、媒介、光线或色彩。用户已经给出细节时，整理优先级即可。简短需求可以补有用的构图或质感，避免擅自增加人物、品牌、道具或文案。
- 有画面文字时，用引号标出必须逐字呈现的内容，说明位置、层级和可读性要求。用用户的语言保留原文。
- 有参考图时，用 `reference_images` 传入实际引用。在提示词里按数组顺序说明图 1 提供主体、图 2 提供配色或风格等。只引用任务需要的图片。
- 用工具 schema 中支持的参数指定比例和透明背景。未指定比例时可以使用模型默认值。透明背景是硬性要求时，先确认工具提供相应选项，不能用白底代替透明背景。

例如，用户要一张给咖啡店做秋季活动封面的图：`{"prompt":"为咖啡店秋季活动生成封面照片。主体是一杯拿铁，放在木桌上，柔和侧光与暖色调。杯子位于下半部，上方留出干净的排字空间，画面不含文字。","aspect_ratio":"3:2"}`

## 修改用户贴上的图片

- 复制会话提供的准确照片引用、工作区相对路径或上一张图的成功回执路径到 `reference_images`。不要猜路径、填系统绝对路径或把图片编码成 Base64 放进提示词。需要先看清工作区图片时可用 `view_image`；聊天模型即使看不到照片，也可以把明确选定的参考图交给生图模型。
- 提示词先说编辑哪张图、改什么及改动范围，再明确保留项，例如人物身份、姿态、构图、商品外形、现有文字或背景。只保留本次相关的约束。参考图有多张时，明确区分编辑目标和其他图各自提供的内容。

例如，用户说把照片里的天空调成傍晚：提示词可写「编辑图 1。只把天空调整成柔和的日落色，保持人物、建筑、取景范围和画面文字。让天空的色温自然衔接地平线。」将图 1 的实际引用作为 `reference_images` 的第一项。

## 检查和迭代

1. 用成功回执里的 `path` 标识这一版。若要判断画面是否满足要求，用 `view_image` 查看实际输出。按本次要求检查主体、构图、原样保留项和文字。只在模型实际收到并看清图片时才声称检查过画面。`view_image` 的视觉副本是 JPEG，不能据此确认原图是否有透明通道。
2. 有具体偏差且仍在用户授权范围内时，选最接近目标的一版作参考，一次修一处，并重申关键保留项。若某个保留项已经丢失，用原图作为编辑目标，按需把中间版本作为辅助参考。每次调用都生成新文件。
3. 简单需求通常一张就够。默认最多追加一次基于画面证据的修正。无视觉输入时，等用户反馈再做需要看图的调整。用户要求多个方案时，每个方案使用明确不同的方向。服务失败、用户拒绝或取消后，依据回执说明状态，避免盲目重试。
4. 成功结果由聊天自动展示。最终回复简短说明生成或修改了什么；有多张时说明推荐哪一版。需要继续修改时，沿用选中版本的路径。
