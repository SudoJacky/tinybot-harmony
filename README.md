# Tinybot for HarmonyOS

使用 ArkTS + ArkUI 编写的原生 HarmonyOS 个人 AI 助手。手机直接连接用户配置的模型服务，数据保存在应用沙箱中；不依赖 Tinybot 桌面进程。

当前是 **原生 Agent 功能增强版**，最低与目标版本均为 **HarmonyOS API 26**。支持独立运行的 Agent、图片与文本附件、工作区文件界面、长期记忆、提示词模板、会话分支和远程 MCP。

当前测试版本为 **0.1.6 / 10006**。参阅[更新说明](docs/distribution/RELEASE-NOTES.txt)、[云测试步骤与验证记录](docs/distribution/CLOUD-TEST.txt)和[交付包准备说明](docs/distribution/START-HERE.txt)。

## 已实现

- **交互回答**：原生组件随模型输出逐步显示，支持分段选择、步进器、勾选清单、图表和本地计算；可复制当前结果或明确提交给模型，交互状态支持重启恢复。窄屏自动堆叠布局，动画与三维内容使用隔离 Web 场景。详见[交互协议、能力与验证](docs/interactive-ui.md)。
- **代码沙箱**：`execute_code` 在独立 QuickJS Runtime 中运行同步 JavaScript，支持 JSON 输入、结构化结果和日志；固定 2 秒预算、32 MiB Runtime 分配限额及输出限制，可取消。聊天、团队与只读模式均可使用，无文件、网络或宿主工具访问。当前为同进程解释器隔离，详见[使用方式与边界](docs/code-sandbox.md)。
- **工具编排**：`orchestrate` 支持异步 JavaScript，通过 `tools` 调用已授权的文件、网页、Skills 和 MCP 工具，处理并发、依赖与数据后统一返回汇总。保留完整子调用回执、原有权限和审批，支持取消与中断恢复；当前不支持后台执行单元或嵌套 Team 控制。详见[异步工具编排](docs/code-sandbox.md#异步工具编排)。
- **聊天 Team 模式**：输入 `/team` 或 `@team` 后描述目标，主 Agent 自主招募员工、分派依赖任务并在原聊天中汇总。聊天卡片可查看员工、交接、产物和用量；无需手动配置成员或确认计划。
- 原生聊天、会话列表、新建与确认删除；界面跟随系统明暗主题。
- 新对话首条消息保存后，后台使用本轮实际模型生成简短标题（与输入语言一致，最多 28 字符）。起名请求不携带历史或工具，不阻塞回答；结果在前台操作结束后保存并刷新会话列表。失败时保留首句摘要，手动改名始终优先，归档或删除的会话不会被晚到结果改写。
- 默认工作区位于应用级 `ApplicationContext.filesDir/workspace/`，每个会话使用 `<会话ID>/` 子目录，无需额外存储授权。新建空会话立即保存，重启和切换沿用同一目录；已有会话启动时自动补建目录。
- 工作区路径按会话 ID 在运行时推导，拒绝路径穿越和符号链接目录。创建目录失败会明确提示；删除会话保留工作区文件，卸载应用或清除应用数据仍会清除这些文件。
- 通过注册表选择 DeepSeek、DashScope、OpenAI、Z.ai、Ollama 或自定义兼容服务；提供与桌面 Tinybot 对齐的模型预设，仍可手动填写模型名称和地址。添加服务与已添加服务列表显示对应品牌 Logo，单色标志适配明暗主题，自定义服务使用通用图标；资源随应用打包，无需联网加载。支持 Chat Completions、OpenAI Responses 和 Anthropic Messages 三种流式协议。
- 增量文本显示、停止生成、失败后重新编辑发送；明确区分完整、停止和失败状态。
- Agent 循环支持流式工具参数、多步执行和同一步多个工具，工具结果以对应的 `tool_call_id` 回传模型；只有模型流完整结束后才会执行工具。
- 内置 `list_files`、`read_file`、`write_file`、`search_file_content`、`read_file_lines`、`edit_file`，仅访问当前会话的工作区。读写限 UTF-8 文本和 64 KiB，列表最多 200 项；文本搜索最多扫描 200 个文件并返回 100 处匹配，行读取最多 200 行，精确替换要求原文只出现一次。截断明确标记；拒绝越界路径与符号链接。写入自动建父目录，以临时文件和重命名完整覆盖目标文件。
- 每轮最多 200 次模型调用、每步最多 8 个工具，顺序执行；最后一次模型请求若仍要求工具，会停止并说明原因。工具失败作为错误结果交给模型处理；流式协议或持久化错误会终止本轮。
- 工具执行前保存意图、执行后保存结果；聊天中可展开查看参数和结果。停止会取消网络请求并阻止后续工具；已提交的写入保留，不自动回滚。重启后不自动重放工具，执行中断且无结果的调用会标为结果未知。
- 聊天执行过程按正文分组，thinking 显示单行预览，工具行可展开查看结果和原始记录；长文本按需分段展开并可收起。展开状态在消息级保留，收起外层或接收流式更新后不丢失阅读选择；主动展开过程后，回答完成不会强制收起。重新加载历史使用紧凑默认状态。
- 运行中可追加指令，或将后续任务加入当前会话队列。支持查看、撤回编辑、移除和继续队列；停止、出错和重启后保留待办并暂停。
- `read_web` 直接读取指定 HTTP/HTTPS 网页的静态正文、标题和来源链接，不需要额外密钥；设置中可关闭。当前不接搜索服务，不登录或执行网页 JavaScript。
- Skills 管理支持导入或粘贴 `SKILL.md`、添加文本参考文件、编辑、启停、删除和显式调用。模型先看到名称与简介，再通过 `read_skill` 按需读取正文或参考文件；脚本不执行。
- API Key 使用 Asset Store Kit 保存，并禁止跨设备同步；更换服务商或服务地址时需重新填写密钥。旧设置迁移为自定义兼容服务，保留已有地址、模型和密钥。
- 通过临时文件、`fsync` 和重命名保存会话；保存失败保留页面内容并提供重试。
- 应用中断后的生成记录标为已停止，不伪装成完整回答；下一轮保留工具结果，避免模型误认为已完成的文件操作被撤销，未完成的回答文本不进入上下文。
- ArkTS 本地测试覆盖流式分帧和工具参数组装、多轮执行、取消、步数限制、执行前落盘失败、工具错误恢复、历史协议还原及工作区路径边界，也覆盖 provider 注册、配置快照、事件顺序和运行收尾。

回答使用原生 Markdown 组件展示，支持标题、强调、列表、引用、代码块、表格和 HTTP(S) 链接。代码块可复制，表格与代码横向滚动；普通 Markdown 不执行 HTML 或远程脚本，独立的交互 Web 节点见[交互式回答](docs/interactive-ui.md)。会话在发送前及生成结束时保存；强制结束进程可能丢失本轮尚未落盘的增量文本，但已保存的历史不会被覆盖为假完成状态。会话迁移为 v2 索引和独立会话文件：只重写变更的会话，先保存内容，再原子切换索引；原 v1 文件保留。当前仍一次加载会话元数据和消息，聊天界面分批展示，尚无磁盘按需加载。图片独立保存，不把 Base64 写入会话记录。支持按预算自动压缩和手动压缩较早上下文，保留完整历史及工具回执。

## 手机端功能入口与边界

- 输入框中的 **麦克风胶囊**使用鸿蒙 Core Speech Kit 离线识别中文（包括中文语境下的英文），首次使用申请麦克风权限。点按开始、再次点按停止；按住说话、松手结束，左滑或点“取消”撤销本次听写。胶囊展开显示计时与语音活动动效，文字实时写入 composer，原草稿保留，仍需手动发送；切到后台或离开聊天停止录音并保留已输入文字。每次最长 10 分钟，不保存录音、不调用模型服务。依赖设备的系统识别引擎；拒绝授权或引擎失败会明确提示。接入与验证见[语音输入](docs/speech-input.md)。
- 输入 `/compact` 并发送，或从 `/` 命令建议中选择，即可调用当前模型压缩较早上下文；完整记录保留，不新增聊天消息。失败时命令留在草稿中，压缩期间新输入的内容不会被清空。
- 输入 `@` 搜索其他会话标题，或从 **+ → 引用其他会话** 进入。每条消息最多引用 4 个会话，可预览、移除；发送时携带选择时的文字快照，原会话之后修改或删除不影响已保存的引用。每份快照最多 8000 字符，超长时明确标注只保留最近内容；仅引用完整轮次的正文，不包含思考、附件和工具记录。引用暂不支持任务排队。
- 聊天框 **+**：添加图片或文档附件；右上角更多菜单提供文件、分支、导出和统一设置入口。每条消息最多 4 个附件；文本限 64 KiB / 32000 字符；图片原文件限 20 MB，最长边缩小至 1600 px 并转 JPEG，结果限 4 MB。需要选择支持视觉输入的模型。附件消息可单独发送；任务队列目前仍只接受文本。
- **文件**：浏览当前会话工作区、打开子目录、新建/编辑/删除文本、导入材料、保存到系统文件夹和分享。删除需确认；导入使用新文件名。每次文本首次修改前持久保存基线，可预览增删行、保留修改或恢复；恢复前检查当前内容是否变化。新建文件恢复时删除该文件。CSV/TSV 表格预览及文本选段可引用到草稿。
- PDF、DOCX、XLSX、PPTX 附件支持提取文字，原文件最多 8 MB。PDF 最多 100 页、Office 受解压大小限制，文字超过 31000 字符明确截断；保留页码、工作表和单元格等可用位置。当前不做扫描件 OCR、不保留 Office 排版；保存的是提取的文本副本。附件预览中可选择文本引用。
- **设置 → 管理长期记忆**：新增、修改、删除背景资料；范围为所有对话或当前对话。消息上的记忆按钮和长按菜单先调用记忆模型（未指定则使用当前模型）提炼最多 5 条、每条最多 200 字符的候选；可以逐条编辑、勾选或手动补充，确认后才保存，默认仅用于当前对话。长消息只提炼前 12000 字符；助手回复结合前一条用户消息判别依据，不直接作为用户事实。没有新信息、取消或提炼失败都不保存原文。确认时再次去重并记录来源；旧记忆不自动修改。设置首页可独立开启“自动提取长期记忆”，开关立即保存：成功任务后额外调用指定模型，仅从本轮用户消息提取事实，过滤已存在的相同条目，并保存来源会话与消息；不覆盖手动记忆。按最近更新时间在 16000 字符预算内注入；超出时提示模型未加载全部条目。自动提取默认关闭，当前去重为规范化文本匹配。
- **设置 → 提示词模板**：管理常用提示词，使用 `{{input}}` 插入当前草稿；套用后返回输入框供编辑，不自动发送。
- **设置 → 用户文档（USER.md）**：编辑全局 Markdown 偏好文档，填写称呼、背景与回答偏好；保存后从下一轮起附加到所有对话及团队执行的上下文，清空即可停用。系统提示词固定由应用维护，用户文档不能覆盖系统规则或工具权限。旧版自定义系统提示词会原样迁移到此文档，旧版内置默认值不迁移。当前文档内容随本机会话配置原子保存并纳入备份，不在各会话工作区重复创建同名文件。导入备份时，仅在本机用户文档为空时恢复备份中的偏好，保留本机已有的非空文档。
- **设置 → MCP 服务**：配置 HTTPS Streamable HTTP 服务，支持 Bearer Token、无鉴权、OAuth 公共客户端登录。OAuth 使用资源/授权服务器发现、PKCE S256、state 校验、资源绑定及刷新令牌；支持动态客户端注册，也可填写服务方提供的公共客户端 ID。回调地址为 `tinybot-harmony://oauth/callback`，服务需允许该回调；登录期间保持应用进程，可粘贴回调链接。凭据保存于 Asset Store。支持初始化、会话 ID、工具分页、JSON/SSE、连接测试及每个会话独立启停；工具可搜索、按需加载 schema，实际调用逐次确认。取消不承诺撤销远程副作用；未知结果不自动重试。当前不支持 stdio、旧 HTTP+SSE、服务端 sampling/elicitation 或资源订阅。
- 长按消息 **从这里创建分支**：用户消息成为新草稿；助手消息及之前内容进入新会话。原对话不变，附件引用保留。分支使用独立空工作区，历史文件不复制；模型会收到明确说明。
- **会话分支树**展示父子关系，可返回来源消息；会话搜索显示匹配摘要，打开后定位消息并突出显示。
- Agent 可调用 `request_user_input` 显示原生文字、数值、单选和多选表单，提交后继续执行；中断的表单可从工具记录重新填写并继续。`update_plan` 显示待办、进行中和完成状态。
- `publish_data_view` 支持表格、柱状图、折线图、瀑布图及指标卡。数据经过校验并保存于工具回执；显示来源、支持表格排序与 CSV 导出，不执行模型生成的脚本。
- **统一设置**：集中提供模型服务、长期记忆、助手行为、工具与扩展、数据与用量、隐私和语言设置。常用开关立即保存；模型分工与能力使用独立表单保存，备份与恢复为独立子页。
- **关于与帮助**：设置底部提供使用帮助、评分和评论、关于 Tinybot；展示实际安装版本、本地更新说明、公告和可重看的首次使用指引。评分和评论入口直接打开华为系统评价弹窗，支持星级评分与撰写评论。用户协议与隐私政策暂留空并标记待补充。聊天输入框下方常驻“AI可能会犯错，请仔细鉴别。”，支持中英文和系统明暗主题。接入与验证边界见[关于与帮助](docs/about-and-help.md)。
- **统一设置 → 模型分工与能力**：配置模型的视觉支持、上下文窗口、推理强度和流式用量请求；模型服务编辑页可从服务的 `/models` 接口发现模型，仍可手动录入。推理强度适用于兼容 Chat Completions/Responses 的服务，Anthropic 当前使用服务默认。自动路由可指定快速、深度、视觉模型，按图片、问题长度和分析关键词选择；每轮记录实际模型，不更改会话的手动选择。
- 用量账本保存服务实际返回的输入/输出、缓存和推理 Token，以及耗时、首字时间和速度。未报告的指标显示未知，不用估算冒充账单；异常结束仍保留请求记录。备份包括会话、附件、工作区、Skills、模板和记忆，最多 20 MB；导入创建独立副本，现有数据和助手选项不覆盖，模型及 MCP 凭据不导出。恢复保留本机已有 Key、Token 和服务设置，复用能明确匹配的服务；新增或匹配不明确的服务作为停用副本导入，需要配置凭据。
- **Token 用量统计**：从「设置 → Token 用量」打开；侧栏和聊天更多菜单均通往同一设置首页。支持今天、近 7 天、近 30 天、全部时间及服务/模型筛选，展示总量、输入/输出、缓存读取/写入、推理、每日趋势、模型分布和分页请求明细。按本地日期归组，全部时间的趋势图仅展示近 30 天；失败/取消请求中已报告的 Token 仍计入总量，缓存与推理不重复相加，未报告与零明确区分。页面随本机账本更新，不汇总其他设备或服务商账户余额。
- **会话与调用归属**：用量页分为总览、会话、活动、请求；可按会话筛选，并从会话排行展开到轮次和每次 LLM 调用。同一轮的多次调用、标题生成、记忆提取、上下文压缩和团队执行分别记录，按用途及自然周汇总 Token；团队调用保留成员、任务和尝试次数。旧账本仅在请求 ID 能唯一对应会话时补充归属，分支复制不会重复累计，无法确定的记录显示为未归属。新增工具活动记录名称、状态、耗时和 MCP 工具名，Skill 按使用轮次计数，活动次数不折算成 Token，旧记录不补造活动数据。
- **大量用量记录**：请求明细采用稳定游标分页，每页 30 条，翻页替换当前页；会话和轮次每页 10 项，轮次在展开后查询。统计只保存汇总计数，按小批次让出界面线程，合并 300 ms 内的账本通知，过期查询和已关闭页面不会回写。账本按 256 条分块保存，更新只写受影响的块，旧 `usage-ledger.json` 首次迁移后保留恢复副本。当前账本仍在内存中维护索引与记录，启动按块恢复；分页限制的是页面数据和渲染节点，不会截断统计范围。运行 `node scripts/test-usage-performance.cjs` 可验证 10 万条请求的统计、分页、取消和事件循环响应。
- 配置支持 OpenAI 兼容图片接口的模型后启用 `generate_image`，可生成或编辑附件/工作区图片；调用前确认，结果展示在回答中并保存到工作区。未指定图片模型时不提供此工具；图片接口计费不纳入聊天 Token 账本。
- 固定任务规则支持只读工具限制、写入前基线、成功回答归档到“任务结果”目录；自动提取长期记忆默认开启，模型路由和归档默认关闭，可分别调整。
- 系统分享面板可选择 Tinybot 接收文本、链接和图片。内容进入新对话草稿，用户审阅后发送；运行中的任务结束后再接收。仅使用系统授予的 URI，不申请整个图库或外部文件夹权限。
- 本轮不包含项目空间、Agent Graph / 工作流、桌面协作、常驻后台 Agent、对话实时云同步或密钥导出。分享与导出的对话 Markdown 不含附件二进制和模型服务密钥。

### 团队协作（Teams）

对齐桌面端 Chat coordinator 流程：在聊天输入框输入 `/team` 选择命令，或直接发送 `/team 目标`（也兼容 `@team`）。模式保存在当前会话，后续对话继续可用；输入框上方可关闭。单独发送命令只启用模式，不调用模型。

主 Agent 根据需要自由招募、边工作边追加员工和任务，并承担最终整合；不再要求手动配置角色、生成独立计划或点击确认执行。员工继承主 Agent 的模型和会话工作区，使用独立执行记录，不能继续招募或向用户发布最终图表。每个团队支持 1–8 位员工、最多 32 个无环依赖任务，最多 4 个任务并行；同一员工串行处理任务。主 Agent 与员工的工作区工具和确认对话框共用串行通道，避免同时写入或弹出确认。

模型工具使用兼容服务的下划线名称：`team_recruit`、`team_wait`、`team_inspect`、`team_read_result`、`team_control` 和 `team_resume`，对应桌面同名点号工具。招募返回后主 Agent 可以继续自己的工作；等待按提交事件唤醒，不返回空超时或额外发起模型轮次。游标分页避免重复消费结果，主 Agent 提前结束时会等待员工交接并在同一轮继续整合。

员工必须通过 `team_complete_task` 交接摘要、未解决事项和实际产物路径，成功落盘后才对主 Agent 可见。支持 research / execution / review 权限范围：research 使用文件与网页工具；review 只读；execution 继承已启用工作工具。员工可用 `team_list_messages` 和 `team_read_message` 读取本团队交接。交接文本产物保留原始内容，主 Agent 读取时核对当前文件；文件变化会报错，不把新版冒充旧结果。仅支持已有 64 KiB 文本工具范围，每次交接最多 8 份文件、总计 128000 字符。

停止聊天会取消本轮启动的所有员工并等待收尾。暂停停止派发并等待正在执行的员工完成；失败、中断或取消任务必须明确重试再继续，不自动重放文件或远程副作用。重启保留模式、团队、尝试和交接，运行中的工作标为中断。团队工具只能访问本聊天的团队；原有手动团队记录以聊天末尾的“历史团队”卡片保留只读查看。手机系统终止应用后不承诺继续运行。

团队功能全部收在聊天中，不再保留独立团队页面及菜单入口。团队卡片默认展示成员和完成进度；原地展开后可查看任务、交接摘要、未解决事项、产物路径和用量，任务详情中可继续展开执行记录。最终回答始终在主聊天中，文件从本会话工作区查看。团队用量展示员工已报告 Token；主 Agent 请求在原聊天和全局账本中，未报告用量标为未知。备份包含团队记录和文本交接，恢复时重映射所属消息、团队及模型引用。

## 运行中追加指令与任务排队

聊天输入框在执行期间保持可用：

- **追加指令**：沿用 Pi Agent 的 steering 语义。等待当前模型响应和整批工具调用完成，在下一次模型请求前按顺序接收一条追加指令；不打断或回滚正在执行的工具。即使模型本来准备结束回答，有待接收指令时也会继续响应。
- **加入队列**：当前任务成功结束并保存后，自动依次启动后续任务。每项任务是独立的用户/助手轮次，保留各自的 200 次模型调用上限和上下文预算；追加指令优先于后续任务。
- 待发送列表可展开、收起、**撤回编辑**或**移除**。撤回时若已有草稿会提示先处理草稿；队列执行不会清空另行输入的草稿。空闲时也可以先添加多个任务，再点击**继续队列**。
- **停止**会终止当前执行并暂停后续任务；模型或保存错误也会停止自动续跑。未开始的指令保留，重启后始终暂停，点击**继续队列**才恢复。手动发送新消息不会恢复已有的暂停队列。
- 队列按会话分别保存，最多 20 条，每条最多 24000 字符；沿用当前会话选择的模型。运行时不能切换会话或模型。追加指令记录在它进入模型上下文的位置，参与历史回放、搜索和上下文压缩；消费指令与记录历史在同一次检查点保存。
- 当前运行固定工具和 Skills。运行中用 `/skill:名称` 切换 Skill 时，请使用**加入队列**，在下一项任务开始时加载。已有待办暂停时，新一轮也保持该队列暂停，可继续加入待办。

本地测试覆盖指令顺序、整批工具边界、无工具回答后的追加、取消、落盘失败、上下文和步数限制、历史回放与压缩、会话隔离和重启恢复。真机使用本地模拟模型验证追加后连续执行多个任务，以及停止、错误、重启、撤回编辑和恢复执行。

## 网页读取与 Skills

在聊天中发送“读取并总结 https://example.com/”，模型可使用 `read_web`。网页读取默认启用，可在 **设置 → 允许读取网页** 关闭；停用后既不向模型提供工具，也不接受该工具调用。

- 仅支持 HTTP/HTTPS GET，不接搜索服务，不携带模型密钥、登录 Cookie 或自定义认证头。地址不能包含用户名和密码；每次重定向重新校验协议，最多跟随 5 次。
- 一次读取含重定向最多 30 秒，响应最多 1 MiB；HTML 提取静态正文与标题，文本、Markdown、JSON 等按文本返回。正文最多 20000 字符、链接最多 30 个，超过时分别标记截断。
- 脚本、样式等不进入 HTML 正文；不会执行 JavaScript、绕过登录或验证码。PDF、图片、无正文页面、不支持的编码和 HTTP/网络错误会明确返回失败。
- 网页结果带有来源 URL 和 `trust: untrusted`，作为资料交给模型；停止会销毁正在进行的网络请求，阻止后续工具。网页内容仍可能不完整或过时，引用应保留来源并说明截断。

在 **设置 → 管理 Skills → 添加** 导入单个 `SKILL.md` 或粘贴其内容，检查后保存。例如：

```markdown
---
name: page-summary
description: 总结用户提供的网页，提取要点并保留来源链接
---

先读取用户提供的网址，再整理三个要点。保留来源 URL；读取失败或正文截断时明确说明。
```

Skill 引用 `references/guide.md` 等文件时，在编辑页填写相同的相对路径，再导入或粘贴参考文本并点击“添加参考文件”。这些内容作为副本保存在本机；没有持续的外部目录授权。当前不批量导入目录或 ZIP，不运行 Shell、Python、Node.js 或 Skill 内脚本。

- 元数据支持 `name`、`description` 的普通/引号文本及 `|`、`>` 多行文本；不是完整 YAML 实现，对这些字段中的对象、引用或无效值明确报错。其他元数据保留在文档中，不授予工具权限。
- 支持 `disable-model-invocation: true`，该 Skill 只在用户显式调用时提供给模型。点击“使用”会把 `/skill:名称` 放入聊天草稿，也可手动输入 `/skill:page-summary 读取这个链接……`。
- 默认仅把已启用、允许本轮使用的 Skill 名称和简介加入上下文；`read_skill` 读取正文时列出参考路径。未导入参考文件、越界路径、重复名称或未启用的 Skill 均明确报错。
- 每次运行固定可用 Skill 及其正文副本；工具结果按现有检查点落盘并参与历史回放。之后停用或删除不会删除旧对话里已经读取的资料。
- 最多保存 20 个 Skills，每个最多 16 个参考文件。单个文档最多 32000 字符，所有文档合计最多 512000 字符；文件选择器单次导入只接受最多 64 KiB 的 UTF-8 文本。

本地测试包含 Skill 元数据/资料校验、手动调用限制、工具启停、网页正文提取、截断与错误、取消，以及通过真实 Agent Loop 读取 Skill 和网页后保存、恢复调用结果的流程。

预设只是填写入口，不代表账号已经开通相应模型。打开设置不会覆盖现有配置；选择内置服务会应用它的默认值，自定义兼容服务保留当前草稿。可保存多份服务配置，每份分别管理协议、地址、密钥、模型列表和启停状态。每段对话独立选择模型，也可设置新会话默认模型；删除或停用服务后会提示重新选择，不自动切换其他服务。同一服务基础地址下切换协议或修改名称、模型、上下文窗口等设置会保留原密钥；更换域名、端口、HTTP/HTTPS 或服务基础路径时需要重新填写密钥。

Ollama 通过其 [OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility) 连接服务器，不在手机内运行模型。填写例如 `http://192.168.1.100:11434/v1` 的实际服务器地址，确认手机能访问该服务器；`127.0.0.1` 指向手机本身。选择 Ollama 时清空云端地址/模型并默认启用“无需 API Key”，使用受保护的代理时可关闭该开关并填写密钥。服务配置允许显式填写 HTTP 以连接本地模型；云端服务建议保留 HTTPS。无需增加系统权限。

GLM 等模型返回的 `reasoning_content` 会独立组装，随工具步骤保存，并由支持该字段的适配器回传；不会混入最终回答。OpenAI 的请求不携带这个厂商扩展字段。[智谱文档](https://docs.bigmodel.cn/cn/guide/capabilities/thinking)明确说明 GLM 5.3 不支持关闭思考，因此本实现保留协议上下文，不通过强行禁用思考绕过多轮工具调用。

## Provider 与运行管理

结构参考 pi 的 provider 工厂/注册表、有状态 Agent 和独立 agent-loop：

```text
ArkUI 页面 → ChatViewModel → SessionService → AgentRuntime → runAgentLoop
                 ↑               ↓                              ↓
             状态投影         会话 / 队列                    ModelSession
                              ↓                              ↓
                         SessionRepository              ModelProvider
                              ↓                              ↓
                         ConversationStore              协议与网络适配

NativeSessionService：组装原生文件、工作区、凭据、网络和 ProviderRegistry
```

`ProviderRegistry.register()` 按稳定 ID 注册服务商；重复 ID 和未知服务商均明确报错。开始运行时，`bind()` 固定 provider 实例、地址、模型和凭据别名，后续设置或注册表修改不会改变正在执行的任务。密钥在每次模型请求前从安全存储读取。设置界面从服务配置和预设生成选项，不根据模型名称或 URL 猜测服务商。

内置服务元数据集中在 `model/Provider.ets`，`DefaultProviders.ets` 负责注册及协议选项。新增 Chat Completions 兼容服务时，添加 ID、显示名称、默认地址和模型预设，并显式选择其协议兼容选项。新增不同协议时，实现 `ModelProvider` 的 `endpoint()` 和 `stream()`，在该适配器内转换 `ModelMessage`、处理流和工具调用，再注册；无需修改 loop。`tool_calls`、`tool_call_id` 等 HTTP 字段仅出现在模型协议层。

内置云端服务的 API Key 区域下方提供“获取 API Key”链接，在系统浏览器中打开对应的官方控制台。DeepSeek、DashScope、OpenAI 和智谱的地址与 Tinybot Desktop 对齐，OpenAI Responses 共用 OpenAI 的入口，Anthropic 使用 [Claude 官方密钥页面](https://platform.claude.com/settings/keys)。链接来自预设元数据 `apiKeyUrl`，不随服务改名改变；自定义服务、Ollama 和启用“无需 API Key”的配置不显示该入口。

`SessionService` 是会话数据的唯一所有者，不导入 ArkUI 或平台 Kit。它接收存储、凭据和工作区等依赖，负责命令准入、待发送指令、逐项运行、设置提交、压缩及恢复；`waitForIdle()` 等待整次会话操作和队列结束。停止、运行失败或检查点保存失败会暂停后续任务，重试保存不自动续跑。

界面接收脱离内部数据的快照；流式文本通过单条消息事件投影，避免每个增量复制全部历史。`ChatViewModel` 只保留显示状态、编辑器和输入防抖，不再直接访问文件、凭据、工具或运行时。设置保存期间的新草稿在提交后接续保存。

`ProfileSettings` 独立处理配置与密钥提交顺序；`SessionContext` 独立处理预算及摘要提交。用户/助手成对历史仍保持兼容；后续功能增强已加入 v1 到 v2 分会话文件迁移，原 v1 数据保留。`SessionService.test.ets` 使用真实 AgentRuntime 和可控模型/存储，验证队列、收尾保存、停止与恢复、草稿隔离、配置和密钥回滚、压缩回滚及观察者隔离。

`AgentRuntime.run()` 接收会话 ID、模型配置、历史和工具；一次只允许一个活动任务。`subscribe()` 发布运行、模型步骤、文本增量及工具事件，`abort()` 取消本轮，`waitForIdle()` 等待本轮收尾。订阅用于同步更新 UI；必须等待的持久化放在 `checkpoint()` 中。最终状态投影和保存完成前仍禁止新任务进入，网络迟到的文本回调不会改写已结束的回答。

`runAgentLoop()` 只依赖绑定的模型会话、工具和取消信号；不访问 ViewModel、凭据或注册表。默认最多 200 次模型请求，调用方可将上限降低为 1–200。工具仍顺序执行，执行前后等待持久化检查点。停止不掩盖真实保存错误，也不撤销已完成的写入。

已经移植模型发现、树状会话分支、运行中追加和任务队列等语义，并实现远程 MCP OAuth。当前没有模型服务账号的 OAuth 登录或通用扩展插件运行环境。

## 模型默认值与固定限制

上下文预算按「单模型覆盖 → 服务覆盖 → 模型默认值」解析。服务高级设置和助手的模型能力设置均可留空恢复自动值；通用默认 **200000 tokens**，`deepseek-flash`、`deepseek-v4-flash`、`deepseek-v4-flash-vision-exp`、`deepseek-v4-pro`、`glm-5.3`、`glm-5.3-flash` 默认 **1000000 tokens**。这是客户端的预算，不会改变服务器实际支持的窗口。已有显式数值（包括旧配置中的 32768）保留，避免覆盖手动配置；清空服务与单模型的覆盖值后使用新默认值。模型规则集中在 `ConversationContext.ets`，适用于同名模型的自定义代理。

正常对话不再主动设置 Chat Completions 的 `max_tokens` 或 Responses 的 `max_output_tokens`，由服务决定默认输出长度。[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create) 要求 `max_tokens`，目前协议层保留 4096 兜底。压缩和记忆提取属于独立的短输出任务，仍使用专门预算。输入预留与摘要输出预算分离，均不作为正常回复输出上限。

点击输入框的上下文圆圈，可查看当前预计占用、剩余容量，以及系统指令、工具定义、用户输入、助手内容、工具结果、历史摘要、附件与引用、消息格式开销的分类估算。分类可展开到指令段、具体工具或保留消息所属的轮次/步骤；草稿与待发送附件另计。分类基于实际请求投影，已压缩历史和仅保存在本地的编排子回执不会重复计入，大工具结果只计发送的预览。分类合计是启发式估算，不强制等于服务端用量校准的占用。生成中展示最近一次请求的内容；空闲时重新估算当前保留内容。

同一面板独立展示最近一次请求和本轮聊天记录的实际输入、输出、缓存与推理用量。未报告显示未知，部分上报标记“部分”；缓存包含在输入、推理包含在输出，不重复相加。标题、记忆整理和团队员工的独立请求不计入此处的聊天轮次，完整请求统计仍在设置的 Token 用量中。展开明细仅作展示，不会发起模型请求；原有压缩操作保留。
